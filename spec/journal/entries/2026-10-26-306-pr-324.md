# Add deterministic collection-position replay

_Drafted from [#324](https://github.com/team-poem/cairn/pull/324) by solp721. Edit this in place; do not delete and re-add it._

## What

Add opt-in `target.collection` to select the current first/Nth item within an identified collection on each replay, without freezing a particular resource.

```ts
target: {
  collection: {
    root: { role: "list", name: "Search results" },
    itemRole: "listitem",
    target: { role: "link" },
    order: "dom",
    index: 0,
    expectedCount: 3,
  },
}
```

Chrome validates complete membership, declared conditions and exact-node continuity before dispatch. Initial support covers named light-DOM lists/listboxes, native listboxes and unnamed role-only actions. Collection-based custom selects are refused before opening; native selects remain supported.

## Why

Existing `nth` distinguishes duplicate accessible names, not positions within a collection.

An explicit positional contract must not silently choose a neighbor when membership, ordering or prerequisites change. Collection declarations remain intact across persistence and replay, and automatic healing cannot replace them with a different flow. Goal assertions remain separate.
