# 2026-09-02 — 프로브 픽스처를 CI에서 돌린다 (레이아웃이 필요한 유일한 지대)

- **브랜치:** `chore/probe-fixtures-in-ci` (`fix/176-hit-test-duplicate-names` 위에 스택 — 프로브가
  아직 develop에 없다)
- **문제:** #176의 in-page 프로브는 요소 박스·히트 테스트·조상의 computed overflow/position을 읽는데,
  **이건 레이아웃 엔진만 답할 수 있다.** jsdom은 전부 0을 돌려주므로 단위 테스트는 **스크립트 문자열**밖에
  못 고정한다. 그 결과 리뷰 세 라운드 동안 **초록인 채로 빠져나간 버그가 셋**이었다:
  ① 문자열 조립 중 `\s`가 삼켜져 공백 정규화가 문자 "s"를 지우는 정규식이 됐고,
  ② 스크롤 클립 판정을 잘못된 축(히트한 요소 위치)으로 짰고,
  ③ `position: fixed`가 조상의 overflow 클립을 벗어난다는 걸 몰랐다.
  셋 다 내가 손으로 브라우저를 열어서 잡았다 — 즉 **사람의 습관에 의존하는 검증**이었다.
- **구현:** `test/fixtures/probe/*.html` 6개 + `test/browser/probe.browser.test.ts`.
  각 파일이 레이아웃 하나이고 기대값은 **버킷 객체 전체**다 — 프로브가 틀리는 방식은 role이 빠지는 게
  아니라 **엉뚱한 버킷에 들어가는 것**이라서 부분 단언으로는 못 잡는다. 픽스처는 지금까지 리뷰에서 나온
  형태 그대로다(모달+백드롭 · 접힌 화면 아래 · 스크롤 컨테이너에 잘림 · 같은 컨테이너에서 보임 ·
  컨테이너 안의 fixed 모달 · `input[type=submit] value`).
- **분리 이유:** 기본 `npm test`에서는 제외한다(`vitest.config.ts`). 브라우저 없는 클론에서도
  587개 순수 테스트가 그대로 초록이고, 브라우저 스위트는 `npm run test:browser`로 따로 돈다.
  CI도 `probe-fixtures` **별도 잡**으로 두어 기존 `verify`의 초 단위 피드백을 안 깬다.
- **브라우저 선택:** Playwright를 쓰되 **`channel: "chrome"`으로 러너에 설치된 Chrome**을 띄운다
  (없으면 번들 chromium으로 폴백). 엔진이 실제로 모는 게 사용자의 Chrome(chrome-devtools-mcp)이므로
  그쪽이 더 충실하고, CI에서 브라우저 다운로드 단계도 없앤다. devDependency는 `playwright` 하나 늘었다.
- **검증:** 로컬 실행 7/7 통과(1.3초). **회귀를 실제로 잡는지 확인**하려고 ③의 두 줄을 잠시 되돌리자
  해당 케이스가 빨개졌고, 복구 후 다시 초록임을 확인했다. typecheck·build·기존 587 테스트 영향 없음.
- **문서:** CONTRIBUTING에 "프로브를 건드렸으면 `test:browser`도 돌리고, 고친 레이아웃을 픽스처로
  남겨라"를 적었다 — 다음 사람이 버그 대신 케이스를 물려받게 하는 게 이 PR의 목적이다.
- **state 변화:** 승격된 규칙("코어가 의존하는 드라이버 관측값은 실물 픽스처로 검증한다")이 프로브
  지대에도 적용됐다. 남은 미검증 지대는 없다고 본다.
