# 2026-09-09 — #198 지각 계약 설계 제안

- **브랜치/기준:** `codex/198-perception-design`, develop `58b3bc8`.
- **결정:** #216 리뷰가 요청한 선행 논의를 위해 `spec/proposals/198-perception-contract.md`에
  미합의 설계안을 작성했다. 관측 사실·랭킹 책임과 관측 요소 참조의 수명을 독립된 결정으로
  나누고, spec 인덱스에서 현재 계약과 구분해 연결했다.
- **현재 상태 정정:** 커스텀 Driver도 discover·explore의 엔진 랭킹을 이미 거친다.
  남은 문제는 관측 입력 계약, Chrome 전용 측정·승격, 팝업 우선순위와 요소 정체성이다.
  locate-heal과 step-heal의 현재 표시 정책 차이도 제안서에 명시했다.
- **제안:** Driver가 측정하고 엔진이 모델 입력을 선택한다. 임시 요소 참조는 의미 기반
  화면 비교 및 영구 Target과 분리하고, 실제 선택 노드를 실행까지 유지한다. 포트 형태,
  팝업 근거·우선순위, consumer perception 변환과 heal 적용 범위는 논의 대상으로 남겼다.
- **검증:** 타입 검사·빌드·의존 경계 검사, 기존 엔진 테스트 1,057개와 벤치 경로 테스트
  5개가 통과했다. 문서만 변경했으며 새 동작의 테스트나 실브라우저 검증을 의미하지 않는다.
- **state 변화:** #198은 열린 상태로 유지한다. 이번 제안은 API 합의나 구현 완료가 아니며,
  합의 후 사람이 검토한 실패 테스트를 바탕으로 구현 PR을 나눈다.
- **교훈:** 임시 관측 주소의 변화와 화면 의미의 변화를 구분해야 no-op 감지를 보존할 수
  있다. 같은 노드의 관측·실행을 보장해도 다음 세션의 업무상 정체성이 보장되지는 않는다.
