# Select a declared position among plain links

_Drafted from [#375](https://github.com/team-poem/cairn/pull/375) by amazon7737. Edit this in place; do not delete and re-add it._

## Why

A host can approve "open the current second post" before discovery. Its grid is made of ordinary links, though, with no accessible list root, so #306 collections could not express it. Legacy `nth` counts only links with the same name. Discovery therefore froze the link it happened to click, and replay reopened that post or asked for repair when the grid changed. The host worked around this by rewriting targets and removing `expect`. #363 carried the approved rule through discovery for ARIA lists. This PR does the same for plain links and checks that each replay arrives where the selected link points.

## What

- `Target.collection.links` declares the collection: `scope` (exactly one element), `member` (a `:scope` selector, where every match is a member), an optional `action` (the link inside a member), and an optional `group: "destination"`. `expectedCount` is required. Position is DOM order.

  ```ts
  { collection: { links: { scope: ".grid", member: ":scope > a" }, order: "dom", index: 1, expectedCount: 3 } }
  ```

- A member's position never depends on how it looks. A badged first card counts. An off-screen member counts and can be selected. A hidden member refuses the collection instead of shifting the position.
- With `group: "destination"`, a card whose image link and title link share one href counts once, and its first link is clicked. Equal URLs in different members are never merged.
- A new binding key pair, `{ source: { kind: "href" }, destination: { kind: "location" } }`, works as discovery `verify` or as a hand-written binding (`LinkSelectedItemBinding`). It compares the selected link's href, read by the final continuity guard immediately before the click, with the top-level URL of the document that received the click, after that step. The guarded click asks for a snapshot in its own MCP reply, and Chrome reads the departure marker and the arrival URL through that snapshot's `RootWebArea` UID. Another tab cannot resolve that UID, even at the same URL, and neither can a document that replaced it, so a decoy tab cannot answer either read. No tab title is changed. Fragments are dropped, the query is compared exactly, and a redirect is compared on where the browser landed.
- Chrome refuses a new-tab link before dispatch. The link's target is its own `target`, or the first `<base target>` when that attribute is missing or empty, as Chrome resolves it. Only an empty target or exactly `_self` counts as the same tab. A download, a same-document link or a non-http link is refused too. Discovery with the link `verify` dispatches through the same check, so it refuses these links before clicking too. If a document marker survives the click, the relation stays unconfirmed. Selecting B and arriving at C fails.
- A changed membership, order, selected node or href before dispatch refuses the click. There is no fallback and no retry. Replay makes zero model calls.
- Links have their own optional Driver ports: `observeLinkCollection`, `clickLinkWithDestination` and `readLinkArrival`. The existing ports keep their 2.9.8 types (`CollectionTarget`, `SelectedItemKey`, `DestinationResourceKey`, `SelectedItemBinding`), so a Driver written against 2.9.8 keeps compiling and never receives a link declaration or key. Without the link ports, a link collection is refused before any action, a link `verify` is refused in discovery, and a replay relation stays unconfirmed. `Target.collection` holds either form as `CollectionDeclaration`. `validateCollectionTarget` returns the form its argument is typed as, so a role-form target still returns `CollectionTarget`, as in 2.9.8. The self-healing wrapper forwards the link ports.
- Spec: `spec/core/link-selection.md`, with pointers from the collection, discovery-selection and selected-item specs and the guide.

Open questions:

- Host code that reads `root` or `target` straight off `Target.collection`, or calls `validateCollectionTarget` with a plain `Target`, still needs a narrowing, because those hold either form. A role-form target gets `CollectionTarget` back, and Drivers are not affected. Is that acceptable for 2.9.9, or should the link form live under a separate `Target` key?
- Discovery with a link `verify` refuses unobservable links but discards the observed destination, as it does for a choice. Should discovery also fail when its own arrival does not match?
- A redirect that changes the URL fails, even when it goes to a canonical form of the same post (`/posts/b` to `/posts/b/`). Should a host be able to declare ignored query names or canonical redirects, or is strict equality right for now?
- A hidden member refuses the whole collection. The alternative is to count it and fail only if it is selected. The strict rule matches #306. Is that what the reporting host's responsive grids need?
- Full navigation usually exceeds the default 2,000 ms source deadline, so replay needs a larger `selectedItemEvidence.timeoutMs`. Should link bindings get their own default?
- Predicate `choice` and `conditions` are not supported on link collections. Add them when a host needs them?
- Validating the reported host's real flow (17 targets) is still to do before telling them they can drop the workaround.
