# Evaluate merge policy only for active requests

_Drafted from [#298](https://github.com/team-poem/cairn/pull/298) by amazon7737. Edit this in place; do not delete and re-add it._

## What

Evaluate merge labels only after a maintainer applies `needs-merge`. Ordinary review PRs skip the optional label check and direct merge job; periodic scans only evaluate requested PRs. Removing a request while an evaluation is queued or running becomes a successful no-op, including after an initial label blocker.

The bot still blocks `no-merge` and `status/1-needs-review`, requires approval and successful current-head CI, and preserves merged-label cleanup and closed-notice updates. The legacy required-check configuration remains disabled; this optional check is not a manual merge-button guard.

## Why

PR #297 passed its real CI but received three failing merge-label checks while it only had the review label. A new PR should not fail a merge-request check before anyone has requested a merge.

Refs #267

No live rulesets were changed. The PR targets `develop`; label/review event behavior and the trusted merge script apply there after merging. Scheduled/default-branch workflow definitions receive their job guard through the normal release to `main`.
