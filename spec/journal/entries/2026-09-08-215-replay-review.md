# 2026-09-08 — #215 리뷰 반영: 목적지·진입 검증·미실행 보고

- **브랜치:** `codex/171-replay-environment`, PR #215.
- **리뷰:** solp721의 코멘트(https://github.com/team-poem/cairn/pull/215#issuecomment-5581193152)에서 지적한 세 동작을 실제 API 호출로 재현했다. 루트 도착의 bare 목적지가 원본 호스트에 남아 실패했고, 진입 호스트 누락은 원본 환경에서 조용히 성공했다. suite 캐시 미스는 미실행인데도 캐시 재생·무료 재생 횟수에 포함됐다.
- **원인과 수정:** 페이지 목적지와 요청 기대값에 같은 보수적 경계를 적용한 설계가 잘못됐다. 페이지의 호스트-only 목적지는 freeze가 루트 URL을 저장하는 정상 형식이므로 goto·expect·wait·navigated와 함께 변환한다. 요청의 호스트-only/root-only fallback 금지는 유지한다. 첫 goto는 허용한 원본 호스트나 대상 origin이어야 하며 아니면 브라우저/LLM 이전에 거부한다. 뒤의 외부 goto는 보존한다. suite는 캐시 미스로 실행하지 않은 상태를 명시해 CLI/Markdown 경로와 무료 재생 집계에 반영한다.
- **테스트 계약 정정:** 기존 테스트가 잘못된 루트 보존 계약을 고정하고 있음을 사용자에게 설명한 뒤 수정·커밋·푸시 지시를 받았다. 해당 기대값과 로컬 failed-test.md를 정정하고 회귀 테스트를 추가했다. 이번 PR에서 추가했던 테스트의 루트 기대값 한 곳만 정정했으며, 기준 develop의 기존 테스트와 하네스 자체는 변경하지 않았다.
- **문서:** 새 환경 재생 가이드를 기존 영어 가이드와 통일하고, trace의 페이지 URL은 런타임 복사본·요청 기대 문자열은 canonical·실제 증거는 실행 환경이라는 구분을 명시했다. skillRef/caseHash는 원본 기준이며 trace 스키마 변경은 필요하지 않다.
- **회고:** URL 검증을 설계할 때 페이지 목적지의 저장 형식과 요청 증거의 식별력을 별도로 확인해야 한다. 설정 오류의 경로도 성공 예시만큼 중요한 실행 계약이며, 발견하지 않았다는 상태만으로 재생됐다고 추론하면 안 된다.
- **상태 변화:** #215에서 리뷰 지적을 수정한다. 최종 원격 확인에서 #217의 병합을 확인해 develop 변경을 통합한다. #218은 아직 열려 있으므로 미병합 변경은 포함하지 않는다. feature branch의 state.md는 수정하지 않는다.
