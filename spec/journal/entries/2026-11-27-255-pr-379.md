# Re-record the order demo with engine 2.9.9

_Drafted from [#379](https://github.com/team-poem/cairn/pull/379) by amazon7737. Edit this in place; do not delete and re-add it._

## What

Re-records `examples/order-demo` with engine 2.9.9 and updates the demo README and the root README to match the new recording (date, engine archive SHA-256, model, per-stage table, defect-stage result). The demo's `cairn-engine` range moves from `^2.9.2` to `^2.9.9`. `record.mjs` gets a one-line change described below.

## Why

@solp721 asked for the order demo to be re-run with engine 2.9.9, with its recording and docs refreshed. The public demo at https://cairn-order-demo.vercel.app still serves the 2026-09-22 recording made with engine 2.9.2, so the README claim "preserved 2.9.2 engine build" and the viewer provenance line are stale against the current release.

One behavior changed. In the 2.9.2 recording, the defect stage lost the original POST 500 from its final request list after outcome re-discovery, and the viewer disclosed that. In the 2.9.9 recording the final result keeps the POST 500 (`orderFailure.finalEvidenceHas500: true`). The docs say so, and keep the old limitation as history for the 2.9.2 recording.

Refs #255 (first order demo)

## Changes

- `examples/order-demo/README.md`: date 2026-11-27, engine 2.9.9, archive SHA-256, per-stage table (defect stage 7 to 6 calls), defect narrative, a note on the recorder change, and the 2026-10-01 deployment check labelled as belonging to the 2.9.2 manifest.
- `README.md` (root, line 30): "preserved 2.9.9 engine build" and the failure stage keeps the original POST 500.
- `examples/order-demo/package.json`: `cairn-engine` `^2.9.2` to `^2.9.9`.
- `examples/order-demo/record.mjs`: the save check compares the loaded scenario with `JSON.parse(JSON.stringify(frozen))`. Engine 2.9.9 returns a discovered scenario with an own `provenance: undefined` key (`packages/harness/src/core/contract.ts`, `{ ...scenario, contract, provenance }`). `saveSkillFile` writes JSON, which drops it, so `assert.deepEqual` failed right after a complete discovery. The first recording attempt stopped there (7 model calls spent, discarded). No stage outcome or assertion on the engine result changed.

The recording itself (`.artifacts/`) is ignored and not committed. The recorded sources match the commit: `record.mjs` SHA-256 `f5840ca2...0f0a21` in the manifest equals the committed file.

## After merge

The Vercel redeploy is a separate step. Until it runs, https://cairn-order-demo.vercel.app keeps serving the 2.9.2 recording. A maintainer or the demo owner runs `npm run build:vercel`, then `vercel deploy` and `vercel deploy --prod` from `.vercel-site` after the new recording is available on the deploying machine (the recording is not committed).

`team-poem/cairn-landing` still describes the demo as engine 2.9.2 in `lib/testing-guide.ts` (line 75 in English, line 153 in Korean: "recorded engine 2.9.2 executions" and "disclose the evidence-retention limitation"). That repo is not changed here and needs its own PR after the redeploy.
