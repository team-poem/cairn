# Refuse stacked squashes and stop waiting on an App-only BLOCKED state

_Drafted from [#319](https://github.com/team-poem/cairn/pull/319) by amazon7737. Edit this in place; do not delete and re-add it._

## What

Two changes to the `cairn-pingu` merge bot:

- **Stacked PRs:** refuse to squash a branch that shares commits with another open develop PR. The notice asks to merge the lower PR first.
- **BLOCKED:** treat `mergeStateStatus: BLOCKED` like `CLEAN` once the bot's own gates pass (labels, approval, `ci.yml` success). Conflicts (`DIRTY`) and other states still wait.

## Why

- **Stacked PRs:** squashing #315, which was stacked on #312, put #312's work on develop under #315's title. #312 was left open with conflicts, #308 stayed open, and the journal skipped #312.
- **BLOCKED:** #316 read BLOCKED to the App on every evaluation from 11:19 onward, while the approver saw CLEAN. All required checks and the approval were in place. The bot required CLEAN, so the PR waited indefinitely.

**Trade-off:** I could not find out why GitHub reports BLOCKED to the App. The App bypasses the develop rulesets, so after this change the bot's explicit checks are the only merge gate. They cover every current develop rule: one approval, `verify` inside `ci.yml`, and `merge-label-policy`. If a new ruleset rule is added to develop, the bot must learn to check it too.
