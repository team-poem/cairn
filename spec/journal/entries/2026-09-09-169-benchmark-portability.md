# 2026-09-09 — #169 벤치마크 실행 경로 이식성

- **브랜치:** `codex/169-bench-portability` (`develop`의 `2f6dbf7` 기준).
- **변경:** 두 벤치 스크립트가 해당 체크아웃의 공개 `dist/index.js`를 상대경로로
  읽는다. discovery와 replay는 호출자의 작업 디렉터리와 관계없이 스크립트 옆
  `bench/frozen/`을 사용하며, 공백이 있는 체크아웃 경로도 처리한다.
- **실행:** 루트 `bench:discover`, `bench:replay`, `bench:churn` npm 명령을 추가했다.
  각 명령은 엔진 빌드 성공 후에만 벤치를 실행하고 인수를 그대로 전달한다.
  `bench/README.md`에 명령, 브라우저·LLM 전제, frozen 파일 위치를 정리했다.
- **검증:** 기존 1,057개와 새 경로·명령 회귀 테스트 5개가 통과했다. 새 테스트는
  루트 `npm test`에 포함되며 격리된 임시 체크아웃과 스텁 엔진으로 실행한다.
  타입 검사·빌드·의존 경계 검사도 통과했다. 기존 테스트·fixture는 변경하지 않았다.
- **범위:** 흐름·모델·측정 출력·재생 횟수·churn 일정은 유지했다. 실제 Chrome이나
  LLM 벤치는 실행하지 않았으며, 이번 검증으로 신뢰성·비용 수치를 주장하지 않는다.
- **state 변화:** #169의 실행 경로 선행 정리를 완료했다. 로컬 fixture 난이도,
  지연 축, 상태 초기화, 표본 수 확정과 #214 비용 비교는 후속 과제이며 이 PR로
  #169 전체를 닫지 않는다.
