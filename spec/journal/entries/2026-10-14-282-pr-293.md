# Support host-provided app context

_Drafted from [#293](https://github.com/team-poem/cairn/pull/293) by solp721. Edit this in place; do not delete and re-add it._

## What

Add optional `appContext` to discovery, exploration and repair, with explicit CLI file loading through `--app-context <file>`.

```ts
await discover(intent, { driver, llm, baseUrl, appContext });
await runScenario(frozen, { driver, llm, heal: true, appContext });
```

- Capture guidance per run/suite case, with a 16 KiB UTF-8 limit and secret substitution.
- Record its hash through existing provenance without rewriting historical results or invalidating cached scenarios.
- Keep guidance separate from final judgment. Policies, live evidence and original repair goals remain authoritative.
- Preserve model-free replay without requiring the description.

No mandatory filename, automatic loading or new context format.

## Why

Consumers currently inject app knowledge into task intent or maintain their own model wrappers. This gives discovery and repair a shared input contract and lifecycle without treating app descriptions as evidence.

Closes #282

`node examples/app-context.mjs` exercises the existing local order demo in Chrome: discovery with/without context, exploration, UI repair, model-free replay of the saved repair, and a real server failure that remains red despite stale guidance. Order payloads are checked independently.

Also passed two browser contract tests and boundary/language/journal checks. Regression coverage includes suite snapshots, credential rotation, getter-backed secrets, whitespace-sensitive substitution and FIFO rejection.

Model responses are scripted. These checks establish integration behavior, not improved model accuracy or token savings.
