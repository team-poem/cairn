# 2.4.0

Archived 2026-09-12. 4 entries from the 2.4.0 cycle.

## Make locale stripping a two-stage match with a consumer-injected prefix list
*#86*

`localeStrippedKey` stripped any two-character first segment as a locale, promoting one app's trait
into a universal heuristic and regressing the #56 fix: real routes such as `/my`, `/go` and `/tv`
were swallowed, so `urlReached` returned true, the expect read as already satisfied, and the click
was silently skipped. The fix applies stage one, a direct boundary match with zero locale
interpretation, and only on failure stage two, the locale-strip fallback. The stripped prefixes
became an injection seam (`UrlMatchOptions.localePrefixes`, surfaced as
`RunHarnessOptions.localePrefixes`, the same pattern as the benign list) with a conservative default
of `["en", "ko", "ja", "jp"]`, region variants matching their base, and `[]` disabling the fallback.
Skips became visible through `ExecutedAction.skipped` and `StepProgress.skipped`, so this failure
family cannot be silent again.

## Stop `new URL()` from silently misparsing schemeless frozen expect URLs
*#87*

Frozen values are schemeless host and path such as `localhost:3000/mentor`, and `new URL()` does not
throw on them but silently misparses, reading `localhost:` as the scheme with an empty host, so the
try/catch fallback never ran and any destination with a port diverged permanently from the first URL
expect in replay. `splitHostPath` now uses `new URL()` only when the input matches `^https?://` and
otherwise splits host and path manually, still falling back to manual splitting when a scheme-bearing
URL is malformed. This completed the URL counterexample corpus in `test/support/url-corpus.ts` at 38
cases, and a full corpus pass became a merge condition for any change in that zone.

## Do not freeze a URL expect for query- or hash-only navigations
*#96*

`assignStepExpects` detected movement on the full URL but froze the expect on host and path via
`destinationKey`, a granularity mismatch. When only the query or hash changed, the frozen expect was
already true on the page before the move, so the replay idempotency precheck silently skipped the
click and reported ok. A URL expect is now assigned only when the destination key actually changed;
otherwise it falls through to the mutation expect, since a fired request is stronger evidence, and
with no mutation there is no expect at all. The regression test was attached to `assignStepExpects`
rather than to `urlReached`, because the lineage is #81 and not #56.

## Register the #96 to #105 issue slate and set the 2.4.0 direction
*#96 · #97 · #98 · #99 · #100 · #101 · #102 · #103 · #104 · #105*

An outside-perspective review plus a full re-read of the roughly 3,500-line core produced a slate and
a release plan. The assessment was that the industry tradeoff, that agent testing is expensive and
nondeterministic so it cannot run in CI, is structurally resolved by amortization, leaving
measurement, turn reduction and sample breadth as the real gaps. Bugs found: #96 expect granularity,
#97 `parseNetwork` matching only numeric status while MCP renders in-flight as `[pending]`, which
made #81's mutation wait dead code in the reference driver, and #98 outcome-heal rediscovering on a
closed driver. Two root causes of the regression chain were named: an app trait promoted into a
universal heuristic, and test-double assumptions diverging from the real adapter. Three design
devices entered the definition of done: trait-versus-fact screening, the URL counterexample corpus,
and the real-fixture rule.
