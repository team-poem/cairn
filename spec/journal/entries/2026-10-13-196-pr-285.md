# Track judgment contract identity across freeze and replay

_Drafted from [#285](https://github.com/team-poem/cairn/pull/285) by solp721. Edit this in place; do not delete and re-add it._

## What

Add judgment contract fingerprints to frozen scenarios and verdicts, with shared Node/browser helpers:

```ts
import {
  identifyScenario,
  runScenario,
  compareContracts,
} from "cairn-engine";

const frozen = await identifyScenario(scenario, {
  intent: "Submit an order",
});

const { result } = await runScenario(frozen, { driver });

compareContracts(frozen.contract, result.verdict.contract);
// "same" | "changed" | "unknown"
```

`contract` identifies judgment inputs; `provenance.appContextHash` separately records creation context. The suite's existing `caseHash` remains a cache key.

Replay recomputes the contract from current checks and judgment settings. Repair keeps the original assertions and captures the context actually used by the judge. Legacy or unrepresentable inputs return `unknown` without blocking custom checks.

## Why

A case can turn red because the judgment contract changed, not because the app regressed. Results need to expose that distinction.

A matching fingerprint means the declared judgment inputs match—not that a failure is necessarily an app regression. App-context loading/injection remains in #282.
