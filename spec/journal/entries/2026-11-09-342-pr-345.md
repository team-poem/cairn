# List each observed element once with its ref inline

_Drafted from [#345](https://github.com/team-poem/cairn/pull/345) by amazon7737. Edit this in place; do not delete and re-add it._

## What

Decision prompts now describe each selected element once. A referenced row carries its ref inline; an unreferenced row keeps its ordinary form:

```text
Interactive elements now on the page:
(A ref is valid for this decision only; use "ref" for exact selection.)
- ref="o1-0" [button] Save (nth=0)
- ref="o1-1" [button] Save (nth=1)
- ref="o1-2" [button] Delete
- [button] Archive
```

Discovery, exploration, surgical step repair and locator repair all read the same `PerceptionObservation.listing`, and choose reference instructions from `hasReferences` (nonempty validated table).

## Why

The ordinary listing and the separate `Current observation references` block repeated the same element descriptions. Replacing the listing with the reference block would lose elements that have no ref, so the two are merged per row instead.

Closes #342

## Scope

- `render` stays ref-free. Explore's dead-action check compares it across observations, and refs rotate every observation.
- Selection, ranking, quotas, binding, validation and dispatch are unchanged. Token format (`o<id>-<index>`) is unchanged.
- Every decision turn still sends the full current listing (#225). Frozen scenarios still carry no runtime refs.
- System prompt wording changed from "current reference table" to "current element listing", and the rejection recovery line from "current observation references below" to "current element listing below". The two pinned system snapshots were updated for that wording only.
