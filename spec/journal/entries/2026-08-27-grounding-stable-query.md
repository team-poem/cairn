# 2026-08-27 — 쿼리 디스패치 API: 안정 쿼리 접두를 프리즌 URL에 남긴다

- **브랜치:** `fix/grounding-stable-query` (`fix/172-ground-stable-url` 위에 스택, PR #178 후속)
- **문제:** #172 픽스가 쿼리를 통째로 버렸다. 경로가 행위를 이름 짓지 않는 API —
  `/graphql?op=AddToCart`, `?action=checkout` 류 RPC — 에서는 프리즌 값이 `shop.co/graphql`이 되어
  같은 엔드포인트의 **무관한** POST(하트비트, 세션 갱신)가 단언을 만족시킨다. 코덱스 교차검증이
  실측으로 잡은 blocker이고, 서로 다른 오퍼레이션 두 제안이 dedupe에서 하나로 합쳐지는 것까지 확인됐다.
  "키만 보존"으로는 안 된다 — `op` 키는 양쪽 다 같고 값이 다르다.
- **구현:** `stableEndpointPrefix`가 경로 뒤에 **안정 쿼리 접두**를 붙인다. 값이 실행별로 변하지 않는
  파라미터를 쿼리 시작부터 이어 담고 첫 run-specific 값에서 멈춘다. 판별은 경로 세그먼트와 같은
  `isDynamicSegment`를 재사용 — `op=AddToCart`는 남고 `buyRequestIds=586738`은 거기서 끊는다.
  **필터가 아니라 접두**인 이유: 프리즌 값은 substring으로 매칭되므로 남긴 파라미터가 쿼리 맨 앞부터
  연속이어야 한다. 파라미터 순서가 실행마다 바뀌는 클라이언트는 쿼리를 아예 안 얼린다(매칭 불가능한
  값을 얼리는 것보다 낫다). 경로가 잘린 경우엔 쿼리를 붙이지 않는다(잘린 경로는 접두라 뒤를 이을 수 없다).
  마지막에 `url.includes(후보)`로 실제 부분문자열인지 확인하고 아니면 경로만 반환 — 트레일링 슬래시나
  인코딩 차이 같은 경계를 한 줄로 닫는다.
- **검증:** typecheck·build·489 테스트(+10). 코퍼스 8케이스 추가(오퍼레이션 보존, 서로 다른 op 구분,
  run-specific 꼬리 절단, 순서 역전 시 쿼리 전체 포기, 값 없는 파라미터, 잘린 경로, 트레일링 슬래시).
  회귀 테스트는 #172의 원래 케이스가 여전히 쿼리를 버리는지 함께 고정. 실앱 도그푸딩은 안 돌림.
- **state 변화:** PR #178 본문의 "Known limits" 1번 해소. 남은 1건(host-only drop이 fail-closed가
  아니라는 것)은 별도 후속.
