# 2.5.0

8 entries from the 2.5.0 cycle.

## Add freeze-less explore mode as a second consumer of the discovery loop
*#102*

`explore(charter, opts)` in `src/core/explore/` reuses the discover loop's machinery (observe,
decide, act, `ActionPolicy`, failure memory, element ranking, `UsageMeter`) but instead of freezing a
Scenario it wanders under a charter and returns an `ExploreReport`. Findings are derived by pure
functions using the same benign and recovered criteria as the critic: `failed-request`,
`console-error`, `dead-action` where a click or select produced no navigation, request or render
change, `action-error`, `slow-settle`, plus a `note` decision letting the model record an
`agent-note` directly. The action vocabulary was extracted into constants shared with discover, so
vocabulary drift is structurally blocked. One observation per turn serves as both the outcome of the
previous action and the input to the next decision. An invariant #4 guard test asserts the replay
path never imports `core/explore`. Known limit: console errors at page load, before the first
action, are not caught, because findings are action-delta based.

## Add runSuite for batch verification of listed QA cases
*PR #124*

`runSuite(cases, opts)` verifies a user's listed QA cases in batch. Per case: a skill cache hit means
deterministic replay only; a miss runs discover once and merges the user's `expect` and `assertions`
into the freeze, on the principle that discover's self-derived assertions only prove what the run
did while the user's expectation is the body of the test; replay uses a fresh driver per case for
state isolation; and a heal triggers a re-freeze so the next run is clean again. The stance is
fail-closed: truncated discovery fails without freezing or replaying, a case crash marks only that
case failed while the suite continues, and config errors are rejected before execution. Dogfooding
on a local demo shop showed three LLM calls per case on the first pass and zero across the whole
suite on the second; renaming "About" to "About us" was absorbed by substring targeting with no heal,
while renaming it to "Our Story" cost one self-heal call and a re-freeze, after which the suite
returned to zero.

## Publish freeze-less explore on a separate npm beta dist-tag
*#102 · PR #123*

Explore was released as a prerelease on the `beta` dist-tag rather than `latest`, following the React
`next` and `experimental` precedent, so a consumer could dogfood without touching stable consumers.
Three safety rules were adopted: a prerelease must always publish with `--tag beta` or it pollutes
`latest`; a stable patch goes through a main hotfix and not develop; and merging develop into main
happens only when the line is decided to be official, at which point the `beta` dist-tag is removed.

## Reimplement select a11y-native first, and add invariant #7 as a guardrail for new verbs
*invariant #7*

Dogfooding found an option picker that was not a native `<select>` but a `button[role=combobox]` with
a listbox portal, and since `select` used the same fill primitive as `type` it was a silent no-op,
causing discover to burn 26 steps. The design judgment inverts the relationship: the a11y-native open
then pick is the general case and native `<select>.value` is the special case, so `select` is like
`type`, an altitude that hides a multi-step mechanism behind one intent. Implementation stayed inside
the driver adapter: `isNativeSelect` probes in-page `tagName` because the a11y role is `combobox` for
both, custom controls throw instead of no-op, and the custom path opens the control, considers only
options that appeared after opening, and clicks by name match, exact first then a single substring,
rejecting multiple exact matches. Invariant #7 bounds verb growth: the test is whether a single
intent freezes more stably than the composition, gated on a real measurement where the composition
was seen to break, so no verb is invented speculatively.

## Frame custom-widget perception as an engine concern and land the perceive seam
*#132 · PR #133*

Dogfooding found a cart checkbox implemented with a hidden input, no `aria-checked` and no accessible
name, where the selected state lived only in a styled span class, so `input.checked` was always
false. Two orthogonal axes were separated: trusted actions, where a JS `.click()` does not reach
controlled components while CDP trusted events do, and state perception, the real gap, where cairn
perceives through the a11y tree like assistive technology and therefore stalls exactly where a screen
reader stalls. This class is undetectable in principle, because a11y reports state confidently wrong
rather than absent. The principle is three layers rather than per-widget DOM hacks in the engine: a
universal driver with trusted actions and a11y perception, a consumer-injected seam for widgets that
break a11y, and filing an a11y bug against the app as the real fix. Shipped: the Driver port now
contractually requires trusted input and a11y-native perception, a `perceive` seam lets consumers
correct snapshot state, and the reference driver promotes roleless click regions.

## Add a case-hash staleness check to the suite cache
*PR #124 review*

`hashCase(c)` over `intent`, `expect` and `assertions` plus the suite-local
`FrozenSuiteScenario = Scenario & { caseHash: string }` were added to `src/suite.ts`, leaving core
`Scenario` and `SkillStore` untouched because they are shared with plain discover, replay and the CLI
(pattern is not data). A cache hit now counts only when the loaded hash matches; a load failure, a
missing hash or a mismatch all fall through to discover, merge and freeze exactly like a miss, so
replay runs only on scenarios discovered in this run or hash-verified. Both heal paths were found to
already preserve the user-merged assertions, and only a confirming test was added.

## Propose a pageContext seam for injecting per-step place knowledge
*proposal, no code change*

Dogfooding showed that discover wanders on unfamiliar pages not primarily from a perception deficit
but from missing knowledge of place: where am I, where do I go next, did that action work, what is
invisible. The measured cost was 22 steps of wandering including clicking an external-navigation trap
link, and a four-iteration re-add loop from not knowing the app's feedback conventions. The proposed
seam is `pageContext?: (url: string) => string | null` on `DiscoverOptions`, symmetric with
`perceive`: perception supplies how things look, `pageContext` supplies where you are. Since this is
host-trusted rather than page-derived text it should sit in a section distinct from page content.
The consumer's own workaround appended the card after the prompt, and because the discover prompt
ends with "Respond with JSON only.", the appended card became the last utterance and buried the
output instruction, which is exactly the class a correctly placed seam eliminates.

## Automate npm release through a GitHub Action
*PR #134*

`.github/workflows/release.yml` triggers on push to main and is idempotent: if the version already
exists on npm it skips everything, otherwise it builds, tests, publishes, pushes a tag and creates a
draft release with generated notes. Existing tags or releases are never overwritten, only flagged
with a warning. The workflow requires an `NPM_TOKEN` repository secret with publish rights and two
factor bypass.
