## Recheck post-conditions after declined repair
*#341 · PR #347*

_Drafted from [#347](https://github.com/team-poem/cairn/pull/347) by solp721. Edit this in place; do not delete and re-add it._

### What

Add an optional `onDeclined` callback to `StepHealer` and recheck the original `expect` once after a no-action repair. If it holds, continue with the original step without retrying the action or recording a replacement, skip, or heal event.

Preserve request watermarks, URL matching, and cancellation/budget handling, including cancellation during failed reads.

### Why

The original navigation can finish while the healer is deciding to return `done`, but replay previously failed without checking again.

A plain `null` can also follow a failed corrective action. Legacy custom healers returning only `null`, and failed or uncertain repair attempts, therefore retain their existing failure behavior.

Closes #341

The browser fixture continued after one original click and one provider call, without a replacement or heal event. Regression tests cover cancellation, request isolation, and rejection of an extra polling window.

## List each observed element once with its ref inline
*#342 · PR #345*

_Drafted from [#345](https://github.com/team-poem/cairn/pull/345) by amazon7737. Edit this in place; do not delete and re-add it._

### What

Decision prompts now describe each selected element once. A referenced row carries its ref inline; an unreferenced row keeps its ordinary form:

```text
Interactive elements now on the page:
(A ref is valid for this decision only; use "ref" for exact selection.)
- ref="o1-0" [button] Save (nth=0)
- ref="o1-1" [button] Save (nth=1)
- ref="o1-2" [button] Delete
- [button] Archive
```

Discovery, exploration, surgical step repair and locator repair all read the same `PerceptionObservation.listing`, and choose reference instructions from `hasReferences` (nonempty validated table).

### Why

The ordinary listing and the separate `Current observation references` block repeated the same element descriptions. Replacing the listing with the reference block would lose elements that have no ref, so the two are merged per row instead.

Closes #342

### Scope

- `render` stays ref-free. Explore's dead-action check compares it across observations, and refs rotate every observation.
- Selection, ranking, quotas, binding, validation and dispatch are unchanged. Token format (`o<id>-<index>`) is unchanged.
- Every decision turn still sends the full current listing (#225). Frozen scenarios still carry no runtime refs.
- System prompt wording changed from "current reference table" to "current element listing", and the rejection recovery line from "current observation references below" to "current element listing below". The two pinned system snapshots were updated for that wording only.

### Size, before and after

Same synthetic discovery fixture (60 referenced links, one decision), three runs each, identical results:

| Build | Decision prompt (characters) |
| --- | ---: |
| `cairn-engine@2.9.7` (npm) | 8,607 |
| this branch | 4,798 |

Character counts only. No tokenizer measurement was run. The fixture names differ from the issue's, so the absolute numbers differ from the 10,203 reported there. The other three consumers were not measured separately.

New `perception-single-listing.test.ts` covers all four consumers with a mixed observation (duplicate referenced rows, an unreferenced row) and a capability change between turns. Both tests fail on develop and pass here. Existing tests that asserted the separate block were updated to the single listing.

## Bound repeated page-guidance expiration
*#340 · PR #350*

_Drafted from [#350](https://github.com/team-poem/cairn/pull/350) by solp721. Edit this in place; do not delete and re-add it._

### What

Stop `discover()` and `explore()` after three page-guidance expirations without a successful action, with a specific result and trace reason:

```ts
{
  truncated: true,
  truncationReason: "page-guidance-expired"
}
```

Successful actions reset the counter; recaptures and rejected decisions do not. Keep existing validation, cancellation and budget handling, preserve perception corrections in the final goal check, and retain exploration's last observed URL.

### Why

A continuously changing page could consume the full step allowance without executing an action. Stop earlier and distinguish this incomplete run from an application defect.

Discovery's final assertion proposal still uses the same execution budget. No additional browser reads or model calls are added to healthy paths.

Closes #340

108 expiration regression cases cover counter resets, mixed failures, references, final goal checks, URL preservation, scroll-policy precedence, cancellation and budget exhaustion.

## Reserve only the missing evidence slots
*#339 · PR #351*

_Drafted from [#351](https://github.com/team-poem/cairn/pull/351) by amazon7737. Edit this in place; do not delete and re-add it._

### What

The evidence reservation in `selectElements()` now fills only the shortfall. Evidence rows already inside the initial cut count toward the five reserved slots, so controls are evicted only when evidence is actually missing.

### Why

The reservation pass always pulled up to five more evidence rows from past the cap and evicted non-evidence rows to make room. With one link and 60 matching text rows at a cap of 60, the link was the only evictable row and dropped out of the listing and reference candidates, popup or not.

Tradeoff: once the cut holds five evidence rows, a later matching row past the cap is no longer swapped in, even if it is the stronger signal (for example a confirmation banner below five weaker matches). Evidence rows tie on score and keep original order, so the reservation does not pick the best five. A test pins this.

Popup evidence counts toward the reservation, so background evidence does not evict the only control while a popup is open. A test pins this too.

Closes #339

The new cases fail without the fix: the control-retention rows at 60 and 140, the partial-shortfall row (55 buttons kept rather than 53), and the observation test that the link is rendered and its ref binds to the original element. A differential run of the old and new selector over 200,000 random inputs (popups, occlusion, clickable regions, caps 0 to 254) found the same length, omitted count and order in every case, with the new selector only trading old swap-ins back for rows from the original cut and never dropping below min(5, old evidence count). Existing #115 rows (reservation with no evidence in the cut, the five-row bound, small and zero caps) still pass.
