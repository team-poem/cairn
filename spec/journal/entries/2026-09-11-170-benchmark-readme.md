## 복구는 한 번도 필요 없었다

앱이 v2로 바뀐 뒤에도 세 단계의 얼린 시나리오가 전부 그대로 통과했다. v2가 실제로 라벨을 바꾸는
것은 확인했다. 픽스처 해시가 다르고, 얼린 타겟이 겨냥하는 이름이 정확히 바뀌는 것들이다. 상태
흐름은 다섯 동작 중 넷의 이름이 바뀐다. 그런데도 통과한 이유는 얼린 타겟이 이름만 들고 있지 않기
때문이다. `{"text":"Log in","role":"button","index":0}`에서 이름이 `Sign in`이 되어도 역할과 위치가
남는다.

그래서 이 수치가 재는 것은 다중 로케이터이지 self-heal이 아니다. 리드미에 두 층으로 나눠 적었다.
역할과 위치가 흡수하는 변경이 1차 방어이고, 그걸로 안 되는 변경에서 self-heal이 2차로 붙는다.
지금 벤치는 2차가 걸리는 상황을 한 번도 만들지 못한다. 즉 제품 핵심 기능 하나가 실측된 적이 없다.
#222 리뷰에서 얼린 `waitFor` 텍스트는 역할·인덱스 대체가 없어 깨진다는 것을 알아냈으니, 그런 변경을
v3로 넣으면 self-heal 경로가 실제로 돈다. 후속 이슈 후보다.

## #221 이후 오히려 싸졌다

같은 이동 단계 파일럿이 #221 전 21호출 $0.167, 후 21호출 $0.132였다. 21% 낮다. 인지 계층이 요소를
더 정확히 주니 같은 호출 수로 끝내면서 토큰이 줄었다. 재생 경과 시간도 2,496ms에서 2,327ms로 줄었다.
#221의 ref 경로가 동작 하나당 MCP 왕복을 늘린다는 우려가 있었는데, 탐색 전체로 보면 비용이 늘지
않았다.

## 리드미

`README.md`와 `packages/harness/README.md` 양쪽에 **Measured** 절을 넣었다. 상태 흐름 차트 하나와
여섯 줄 표, 그리고 교차점·호출 수·복구 없음·정가 기준을 적었다. 차트는 `docs/cost.svg`이고 보고서
JSON에서 생성한 것이라 데이터로 다시 만들 수 있다. 마지막 줄에 "이 여정과 이 일정을 설명하는
것이지 당신 앱을 설명하지 않는다"를 남겼다.

두 리드미가 어긋나 있던 것도 맞췄다. npm 쪽에 #174의 secrets 항목이 빠져 있었다.

실제로 쓴 설정을 `bench/local/cost.claude-sonnet-5.json`과 `cost.claude-opus-5.json`으로 커밋했다.
결과 JSON에 설정이 박히지만 `bench/results`가 gitignore라 남지 않는다. 모델을 추가하는 사람이 같은
일정을 그대로 써야 행이 비교 가능하다.

state 변화: #170을 닫는다. 2.9.0의 마지막 조각이었다. `state.md`의 `~5000배 저렴`은 develop에서
지운다.
