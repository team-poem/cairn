# Relay trusted verification to private OCI execution

_Drafted from [#292](https://github.com/team-poem/cairn/pull/292) by amazon7737. Edit this in place; do not delete and re-add it._

## What

Move trusted `ci / verify` execution to the private OCI executor while preserving the public check identity. Fork and Dependabot PRs keep the original hosted verification commands; browser, document-reference, package-consumer, and release jobs retain their existing execution paths.

## Why

Run the existing verification workload on the project's CI infrastructure without registering a persistent runner to this public repository. The relay validates the exact dispatched execution and fails when success cannot be confirmed. This change does not deploy applications.

Closes #291

- Boundary, language, and journal checks pass; `actionlint` passes.
- Independent review confirmed every original hosted verification command and the other CI jobs are preserved, and Dependabot receives no executor credential.

- Live OCI execution: [successful private repository-dispatch execution](https://github.com/team-poem/oci-ci/actions/runs/38513499881) ran the existing verification on Ubuntu ARM64.
- Public relay: [successful public CI run, attempt 2](https://github.com/team-poem/cairn/actions/runs/38512115729), on PR head `53a687f3823a51bac7ebb08d466b9e5d5e312fd0`, mirrored that exact execution successfully.
- Hosted engine compatibility (Ubuntu, macOS, Windows), document-reference checks, npm/pnpm package-consumer checks, and PR benchmarks also succeeded.

The executor verifies the current source revision before running the existing checks. Production deployment is outside this workflow. Host execution is serialized with the existing CI workloads; queue time counts toward the timeout. Fork and Dependabot checks and the retained platform matrices continue to use GitHub-hosted runners.
