# #170 — 모델별 비용과 비교 차트

`feat/170-per-model-cost`에서 비용 비교 보고서를 모델별로 나누고, 보고서에서 차트를 그리게 했다.
README에 넣을 수치를 만들기 위한 준비이며, 수치 자체는 #225가 고쳐진 뒤에 나온다.

## 한 호출이 모델 하나가 아니다

CLI 한 호출이 모델을 두 개 청구한다. 측정 대상 모델 옆에서 도구가 자기 배경 작업용 작은 모델을
따로 쓴다. 이동 단계 실측에서 그 몫이 전체의 8분의 1 정도였다. 그래서 총액 하나로는 "측정 대상
모델이 얼마였나"에 답할 수 없다. 실행마다 제공자가 주는 모델별 분해를 보관하고, 보고서가 갈래와
모델별로 한 줄씩 낸다. 갈래의 비용 칸은 총액 그대로 둔다. 그게 실제로 쓴 돈이다.

## 구독으로 돌려도 API 환산이 나온다

분해에는 제공자의 `costBasis`가 같이 온다. 확인해보니 `"list"`, 즉 공개 API 정가로 계산한 값이다.
그래서 구독 인증으로 돌린 실행의 비용이 곧 API로 썼을 때의 값이다. 우리가 단가표를 들고 곱할
필요가 없고, 들고 있으면 가격이 바뀔 때마다 틀린 숫자가 되므로 만들지 않는다. 정가 기준이 아닌
몫이나 값이 없는 몫은 무료로 채점되지 않고 그렇게 표시된다.

## 차트는 보고서에서만 그린다

README 그래프는 그것을 낳은 데이터로 다시 만들 수 있어야 한다. 그래서 `cost-comparison` 보고서
하나만 입력으로 받아 SVG를 낸다. 비용 실행은 단계마다 SVG를 JSON·Markdown 옆에 쓴다. 보고서가
교차점을 낼 수 없다고 판단한 단계는 그림도 그리지 않는다. 그림으로 하는 주장도 주장이다.

## 비용 추정을 20배 틀렸다

전체 실행 예산을 저널의 지난 실측(`discover $0.4–0.6` 1회)으로 잡아 두 모델 합계 $80–110으로
말했는데 틀렸다. 그 값은 실제 앱의 다단계 체크아웃을 탐색한 것이고 로컬 픽스처와는 자릿수가 다르다.
파일럿을 돌려보니 이동 단계 6실행 두 갈래가 21호출에 $0.167, 호출당 $0.008이었다. 탐색 1회가
3호출에 $0.024다. 오퍼스는 소넷보다 15% 비쌌을 뿐이다. 픽스처가 작아 입력이 안 쌓이면 호출 수가
같을 때 모델 차이가 거의 드러나지 않는다. **교훈: 다른 조건에서 잰 단가를 새 조건에 곱하지 말고,
가장 싼 단계를 상한 낮게 걸어 한 번 재고 곱한다.** 벤치가 실제 비용을 기록하므로 그게 가능하다.

## 이동 단계에서 나온 첫 수치

소넷5, 6실행, 앱은 4번째 실행에서 바뀜.

| 갈래 | 총액 | 측정 모델 몫 | 호출 |
| --- | ---: | ---: | ---: |
| 매번 탐색 | $0.143 | $0.124 | 18 |
| 한 번 탐색 후 재생 | $0.024 | $0.021 | 3 |

교차점은 2번째 실행. 이 단계는 복구가 한 번도 필요 없었다. 라벨이 바뀌어도 얼어붙은 클릭이
역할·인덱스 대체로 살아남았기 때문이다. 그래서 이 6배는 복구 비용이 들어가지 않은 하한이고,
한 동작짜리 흐름이라 절약이 가장 작게 나오는 자리이기도 하다.

검증 결과: 벤치 테스트 77개(신규 8개), 워크스페이스 1,057개, 타입 검사, 빌드, 의존 경계 통과.
실제 Chrome에 scripted 출처로 `cost`를 돌려 모델별 분리와 차트 생성을 확인했다.
