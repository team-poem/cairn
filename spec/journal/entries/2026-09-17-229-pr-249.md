# Keep a role-less nth on one pool, and nth only over identical names

_Drafted from [#249](https://github.com/team-poem/cairn/pull/249) by solp721. Edit this in place; do not delete and re-add it._

## What

Two silent misclicks in `resolveTargetUid`, both from #229.

A role-less `{text, nth}` resolved over the compact tree on attempt 0 and over the verbose tree on the retry. The verbose tree carries a `StaticText` under a named control that the compact tree collapses, so the same `nth` counted a different pool depending only on whether attempt 0 missed. A role-less positional target now retries over the compact tree. With a role the added rows never enter the pool, so the verbose retry keeps recovering a portal option the compact snapshot omitted.

`nth` also fell through to the substring pool once the exact matches were gone, so a frozen `"Save"` with `nth: 1` clicked `"Save draft"` with no error. The substring pool now qualifies only when its matches are identically named. An authored substring over repeated identical labels still resolves; the Nth of differently-named partial matches is refused, and the error lists the names it found.

`spec/core/targeting.md` records that a position is only meaningful within one pool.

One behaviour to know about. During discovery, a model that names a verbose-only row with `text` and `nth` but no `role` used to click the `StaticText` wrapper, which is the bug above; it now gets one failed turn and the "already failed" line. The prompt already asks for `role` with `nth`, and the role-bearing form keeps the verbose retry.


Closes #229


- Reproduced live with chrome-devtools-mcp 1.8.0. A page with two `Save` buttons, the second rendered 500 ms late so the first compact snapshot misses it: develop retries over the verbose tree and clicks the first button 5/5, this branch retries over the compact tree and clicks the second 5/5. With no late render both click the second, so develop's answer depended on timing. The verbose tree of that page shows `StaticText "Save"` under each button; the compact tree does not.
- Six new tests fail on develop and pass here: the same node resolves whether or not attempt 0 missed and no verbose snapshot is taken; a role-bearing `nth` still recovers a portal option the compact tree omits; `"Save"` over `"Save later"` / `"Save draft"` refuses and names both; and the substring pool with `nth` resolves over identical labels only. Removing the `!target.role` condition, the substring guard, or the cache reset on retry each turns a test red.
- One existing test was rewritten: `{text: "Add", nth: 1}` over `"Add to cart"` / `"Add to wishlist"` used to resolve and now refuses.
- Compatibility smoke (MCP 1.3.0, 3 journeys, zero LLM calls), `test:document-refs` (1.8.0) and the 30 browser tests pass. typecheck, build, 1,210 workspace tests, 183 bench tests, boundaries, language and journal checks pass.
