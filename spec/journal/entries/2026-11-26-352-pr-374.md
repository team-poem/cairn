# Measure a pointer-events none row as a disallowed pointer action

_Drafted from [#374](https://github.com/team-poem/cairn/pull/374) by amazon7737. Edit this in place; do not delete and re-add it._

## What

The Chrome driver now fills in the `actions` eligibility map that #362 added. A row whose computed `pointer-events` is `none` reports `click`, `doubleClick` and `hover` as `disallowed`. A new test pins that a disallowed choice never reaches locator work, and that a snapshot published while the locator resolves does not move eligibility onto or off the bound decision.

## Why

Issue #352 asks the engine to tell observed context apart from action candidates, and to reject an action a Driver or host has measured as disallowed before it is dispatched. The model should then be able to choose the observed link. Missing hints must stay unknown, because a heading or a roleless widget with a working handler is still usable.

#362 shipped the prompt wording and the rejection path. It left two items open: a real Chrome measurement source and a dedicated asynchronous-enrichment test. This PR closes both. Nothing outside the Chrome probe and its tests changes, and the engine contract is untouched.

Why `pointer-events: none`: the pointer falls through to whatever lies beneath, so the driver reports a successful click that never reaches the row's handler. A real Chrome run confirms it, a direct `driver.click` on such a button returns normally and the page's handler never fires.

- A descendant with another `pointer-events` value can receive the pointer and bubble to the row, and a subtree of more than 64 elements is too large to scan. Both leave the row unknown. Only a positive measurement is reported.
- `type` and `select` are not measured, so a click restriction never blocks them. Nothing is removed from the listing.
- An on-screen `pointer-events: none` control already fails the foreground hit test and leaves the listing as occluded. This measurement covers rows the hit test cannot reach, such as offscreen or clipped ones. The value is therefore narrow, and the commit is separate if you would rather drop it.
- `inert` is not measured. Chrome drops an inert subtree from the accessibility tree (checked in real Chrome), so it never becomes a row.
- The page-side script's reply is parsed strictly. Only `disallowed` for `click`, `doubleClick` and `hover` reaches a row.
- Frozen replay gets no new gate. `spec/core/perception.md` records the measurement.

Closes #352
