## Bind host page guidance to the observation a discovery or exploration decision uses
*#304 · in-progress*

`discover` and `explore` accept an optional `pageGuidance` provider. It is called once per decision
observation, after capture, `perceive`, selection and reference issuance, and before the decision
prompt. It sees only the listed rows (role, name, ordinal, three states) and a URL read just before
capture. Its text goes into a separately labeled host section of that one prompt.

The decisions that carry weight:

- **Invalidation is a pre-dispatch URL comparison, not an atomic read.** A guided decision whose
  page URL changed before dispatch is not run. Same-URL changes rely on the existing observation
  identity and reference validation; guidance relaxes neither.
- **Fail open, but never on cancellation.** Provider errors, a 5-second timeout, non-string or
  oversized output (over 4,096 UTF-8 bytes, never truncated) mean no guidance for that decision.
  Caller cancellation and the run deadline still reject the run. Provider time counts against the
  run deadline through the existing budget operation, without a model-call admission.
- **Guidance cannot author checks or identity.** Assertion proposals and judgment never receive it.
  Inline assertions from a guided `done` are discarded. Scenario, provenance, contract and cache keys
  are unchanged.
- **Repair paths and `runSuite` are out of scope** for this change; replay never calls the provider.

Trace moves to 1.12 for `gate: page-guidance`, which carries fixed reasons only.

## Compose separate engine calls and host work under one workflow budget
*#305 · in-progress*

### What

`runWorkflow({ budget, signal? }, work)` owns one allowance, deadline and cancellation signal.
Inside `work`, `workflow.borrow(name)` issues a lease. `discover`, `explore`, `runHarness` and
`runScenario` borrow it through `workflow: lease`, and host-owned model and browser work opts in
through `lease.llm`, `lease.driver` and `lease.operation`. Both the Node and the browser entry
points export it. The contract is in `spec/core/run-budget.md` under "Workflow composition".

Internally, the run budget is split into a shared `Allowance` (count, deadline, signal, in-flight
operations, lifecycle stage) and a per-participant `BudgetScope` (phase, evidence, actions,
usage). An owned run still has exactly one scope, so existing calls and per-case suite budgets
behave as before.

### Why these choices

- **The internal scope class is not exported.** A lease exposes only borrowing operations, so a
  borrower cannot reset or dispose the owner. This is what the issue asked for.
- **A borrowed call throws on exhaustion instead of returning a budget verdict.** The host's
  composition stops at the participant that ran out, so verification cannot start after a
  preparation that was stopped. The owner returns the single stop result.
- **One engine operation per lease.** Each participant's evidence and uncertain operation then
  belong to that call alone.
- **Double-counting is prevented by identity.** The allowance remembers every wrapper it makes and
  unwraps before wrapping again. A lease client hidden inside a foreign wrapper cannot be
  recognized, and the spec says so rather than guessing with async context.
- **No owner cleanup callback.** `runWorkflow` returns only after all admitted work has settled,
  so ordinary host cleanup after it returns already runs once, with nothing in flight.
- **`runSuite` does not borrow.** Suite cases keep independent allowances, as #284 decided.

## Validate guided decisions against page changes and prepare the page-guidance PR
*#304 · in-progress*

This entry supersedes the review-next-step in `2026-10-23-304-page-guidance.md`; the maintainer
requested implementation and PR preparation. The original entry remains an unchanged record.

Accepted guidance is checked before any decision effect, including completion and exploration
notes. Reference-free decisions compare a fresh semantic/perception snapshot with state copied
before the provider ran, so same-URL overlays and even an in-place mutation of a Driver-returned
array invalidate old guidance. Exact-reference actions retain the Driver's mutation guard;
recapturing would rotate their references. URL checks bracket the comparison capture, but this
is an observation-boundary check, not an atomic lock or a claim that invisible/reverted changes
can be detected.

Rebased onto the current `develop` while preserving per-run action-policy lifecycle and
no-progress completion semantics. Trace 1.13 adds the fixed page-guidance diagnostics after
1.12's no-progress changes. Raw comparison state and guidance are never new trace fields.

## Drain complete workflow participants and preserve the first stop cause
*#305 · in-progress*

Review of the workflow owner found that draining port operations alone could return before
a concurrent borrowed call finished its owned-driver cleanup or final trace publication.
The owner now tracks the complete public call separately from its primitive operations.
Entry-local draining still waits only for primitives, avoiding a self-deadlock.

Already dispatched host work may complete during owner draining, while new admissions remain
closed. Failure from unfinished registered work rejects a successful callback value. The exact
promises returned by engine entry points and registered host operations have rejection observers,
so an abandoned sibling does not become an unhandled rejection. Failures explicitly recovered
while the workflow is open remain recoverable. Caller cancellation keeps its original reason
even when a non-cancellable operation settles after the deadline.

and benchmark tests, eight demo tests). Package-consumer validation passes for public types,

## Discard synchronous page guidance returned after the provider deadline
*#304 · PR #322 · in-progress*

An independent review reproduced a synchronous page-guidance provider occupying the event loop
for 5,020 ms, then returning text before the overdue timeout callback could execute. The prior
implementation accepted that late text and cleared its timer without aborting the request signal.

The provider boundary now checks monotonic elapsed time when control returns from either a
fulfilled or rejected provider call. Settlements at or after 5,000 ms expire and the provider
signal is aborted; earlier rejections remain provider failures. An already-aborted caller retains its
original reason. This is cooperative enforcement; JavaScript cannot interrupt a synchronous
callback that has not returned. Error details and guidance remain absent from new trace payloads.

Regression tests move only the monotonic clock while keeping the timer pending, for both returned
values and thrown errors: 4,999 ms preserves the provider outcome, 5,000 and 5,001 ms expire, and
simultaneous caller cancellation retains its original reason with no model dispatch. The same actual 5,020 ms reproduction now discards the result and emits the fixed
timeout diagnostic with an aborted provider signal.

Typecheck, build, dependency boundaries, language and journal checks passed. The full suite passed
1,618 workspace tests, 397 benchmark/script tests and 8 demo tests; the focused guidance suite now
contains 25 tests. Existing real Chrome/MCP guidance and zero-model replay evidence remains in
`2026-10-25-304-page-guidance-verification.md` and its committed reproducible fixture.

## Separate engine and workflow drain ownership for same-lease host wrappers
*#305 · PR #323 · in-progress*

Review of PR #323 found that a host operation could await an engine call using the same lease,
while the engine's drain waited for that host operation. The deadline aborted the signal but
could not break the promise cycle. Starting the engine before registering the host wrapper
produced the same cycle.

Pending operations now carry a drain owner independently of their participant accounting.
Borrowed engine calls drain engine-owned operations. The workflow owner still drains explicit
lease operations and complete engine calls, including cleanup and final publication. Driver
wrappers cache by raw driver and drain owner. Admission counts, evidence and stop attribution
remain on one participant scope.

An entry-only rejection guard would miss the reverse-order case. Rejecting host registration
during an engine call would prohibit supported managed-model callbacks. The ownership split
supports both orders without an async-context dependency or a public API change.

The public-package reproduction returned neither a result nor an error after cancellation.
Eight focused regression cases timed out before the fix. The real Chrome fixture now wraps
both discovery and frozen replay in host operations using the same lease.

Validation passes: typecheck, build, 1,624 workspace tests, 397 benchmark and script tests,
and eight demo tests. The package-consumer check covers public types, the installed CLI, browser
bundling and the real Chrome quickstart. Boundaries, language, journal and diff checks pass.
Independent review passed 72 workflow and budget tests and found no remaining defect.
The real Chrome workflow fixture completes with three discovery model calls and zero replay
model calls. Reproduce after building with `node scripts/test-workflow-budget.mjs`.

## Add deterministic collection-position replay
*#306 · PR #324*

_Drafted from [#324](https://github.com/team-poem/cairn/pull/324) by solp721. Edit this in place; do not delete and re-add it._

### What

Add opt-in `target.collection` to select the current first/Nth item within an identified collection on each replay, without freezing a particular resource.

```ts
target: {
  collection: {
    root: { role: "list", name: "Search results" },
    itemRole: "listitem",
    target: { role: "link" },
    order: "dom",
    index: 0,
    expectedCount: 3,
  },
}
```

Chrome validates complete membership, declared conditions and exact-node continuity before dispatch. Initial support covers named light-DOM lists/listboxes, native listboxes and unnamed role-only actions. Collection-based custom selects are refused before opening; native selects remain supported.

### Why

Existing `nth` distinguishes duplicate accessible names, not positions within a collection.

An explicit positional contract must not silently choose a neighbor when membership, ordering or prerequisites change. Collection declarations remain intact across persistence and replay, and automatic healing cannot replace them with a different flow. Goal assertions remain separate.

Closes #306

Additional verification:
- 1,690 unit tests and 173 browser tests passed.
- Added regressions for native listboxes, unnamed actions, custom-select refusal and shadow-DOM scope boundaries.
- The same frozen scenario selected `alpha`, then `beta`, after changing collection order, with zero LLM calls.
- Added real MCP collection regression coverage to CI.
