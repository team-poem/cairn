# Add predicate-constrained collection selection

_Drafted from [#333](https://github.com/team-poem/cairn/pull/333) by solp721. Edit this in place; do not delete and re-add it._

## What

Add explicit `Target.collection.choice` to select one eligible resource in DOM order. Reuse selected-item bindings so dependent actions and independent review evidence refer to the resource selected in this run.

```ts
choice: {
  version: 1,
  cardinality: 1,
  policy: "first-dom",
  identity: {
    kind: "attribute",
    scope: "item",
    attribute: "data-resource-id",
  },
  where: [{
    kind: "attribute-equals",
    scope: "item",
    attribute: "data-available",
    value: "true",
  }],
  maxReselections: 1,
}
```

The initial API supports hand-authored, same-document collection clicks. This also fixes StaticText receipts and preserves capture timeout diagnostics.

## Why

“Choose any available item” needs an explicit contract. A missing fixed target must not authorize selecting another resource.

When explicitly enabled, reselection is allowed once and only after the driver confirms the previous click was not dispatched. Uncertain mutations are never retried, original assertions remain unchanged, and fixed-target and positional behavior are preserved.

Closes #329
