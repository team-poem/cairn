# #169 — 로컬 신뢰성 측정 실행기

`codex/169-reliability-bench`에서 탐색·재생·복구를 분리한 로컬 측정 실행기를 추가했다.
세 단계는 단순 이동, 비동기 폼 저장, 로그인·장바구니·주문이다. 매 시도는 새 서버와
격리 브라우저를 소유하고 정리까지 기다린다. 지연은 경로 종류와 시도 인덱스로 고정하며,
요청한 지연과 관측 시간을 별도로 남긴다.

탐색은 공개 엔진이 생성한 Scenario와 출처·해시를 저장한다. 재생은 LLM 호출을 차단하고
원본을 유지하며 새 서버 주소에 연결한다. 엔진 판정·증거와 서버의 완료 상태를 별도로
보존하고, 예외를 포함한 전체 시도 수를 JSON 및 Markdown으로 보고한다. v2의 성공은
역할·인덱스 대체 탐색으로도 가능하므로 복구 횟수와 LLM 호출 수를 함께 해석한다.

실제 측정을 위한 Claude Code JSON 완료 인터페이스는 명시적인 모델·호출 수·비용
중단 기준을 요구한다. 실패한 호출의 알려진 비용도 합산하며 비용이 불명확하면 후속
유료 호출을 멈춘다. 사후 비용 기준은 마지막 호출만큼 초과할 수 있어 결제 상한으로
표현하지 않는다. scripted 탐색은 엔진 통합 확인이며 실제 LLM 탐색 성공률과 합치지 않는다.

검증 결과: 승인된 오프라인 동작 사례 24개를 추가했고 기존 테스트·헬퍼·픽스처는 보존했다.
전체 1,086개 테스트, 타입 검사, 빌드, 의존 경계 검사와 최종 게이트를 통과했다.
깨끗한 `fda85cc`에서 공식 CLI와 실제 Chrome으로 scripted 탐색 3/3, 재생 9/9를
확인했다. 탐색 완료 호출 수는 단계별 4·5·10회였고 재생의 LLM 호출은 모두 0회였다.
재생은 단계별 3회씩 실행했으며 정리를 포함한 평균 시간은 이동 2,910ms, 폼 4,185ms,
상태형 5,332ms였다. 문서 지연 `[0,20,80]`, API 지연 `[0,40,150]`을 사용했다.
환경은 Node 26.5.1, Chrome 153.0.8010.36, MCP 요청 버전 `~1.3.0`이었다.
Claude 전송 인터페이스는 오프라인 가짜 실행 파일로 비용·실패·사용량 보존을 확인했으며
유료 호출은 하지 않았다.

상태 변화: #169는 로컬 픽스처·지연·초기화·출처를 갖춘 측정 명령을 사용할 수 있다.
실제 LLM의 모델·예산·독립 표본 수 선택, 큰 N과 기준선 측정은 남아 있으므로 이슈를
닫지 않는다. #214의 비용 비교 실험과 #220의 CI 분리는 이번 변경에 포함하지 않았다.
