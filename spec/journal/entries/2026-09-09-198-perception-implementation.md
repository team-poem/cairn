# 2026-09-09 — 지각 정책과 관측 시점 요소 주소 지정 (#198)

- **브랜치:** `codex/198-perception-design`, PR #221.
- **문제:** 뒤에 붙은 포털 옵션이 프롬프트 예산에서 잘리고, 이름으로 다시 찾는 실행은 관측한 동명 요소와 다른 노드를 선택할 수 있었다.
- **변경:** Driver의 선택적 관측 사실(`inActivePopup`, `occluded`, `clickable`, `clickableRegion`)과 임시 `ref`를 추가했다. discover·explore·step-heal·locator-heal이 같은 관측 및 선택 정책을 사용한다. 팝업 우선순위·클릭 영역 중복 제거·증거 예약은 엔진이, DOM 측정은 Driver가 담당한다.
- **주소 계약:** 모델에는 관측별 토큰 표를 전달하고 원래 Driver ref는 숨긴다. 정책 검사는 실제 이름·역할·전체 스냅샷의 중복 순번으로 수행한다. 현재 관측과 결정 내용을 실행 직전에 재검증하며, 실패한 ref를 이름으로 재해석하지 않는다. freeze에는 기존 Target 필드만 남고 재생은 LLM 없이 실행한다.
- **Chrome:** 전체 접근성 트리에서 가상 InlineTextBox를 제외하고 정확한 MCP UID를 사용한다. DOM 변경·노드 교체·탭 전환·재관측·실행은 이전 ref를 무효화한다. 모든 속성 변경을 감시하며, shadow/frame 등 감시 밖 후보가 하나라도 있으면 공통 순번의 안전성을 보장할 수 없어 관측 전체의 ref를 생략한다. 서로 다른 프레임이나 분리된 노드 때문에 측정 배치가 실패하면 배치를 나눠 측정 가능한 후보의 사실을 보존한다. compact 트리가 생략한 포털 옵션은 재생 시 전체 트리로 재시도한다.
- **호환성과 범위:** 기존 Driver는 선택 필드 없이 동작한다. 소비자의 perceive는 참조가 있는 요소를 필터링·재정렬할 수 있지만 이름·역할을 바꾸거나 ref를 재사용할 수 없다. DOM에만 존재하고 캡처되지 않는 무명 위젯 및 프레임워크 내부 상태는 소비자 Driver/perceive의 책임이다. locator-heal도 설정된 비밀값의 value 마스킹을 적용한다.
- **검증:** 타입 검사·빌드·의존 경계 검사 통과. 전체 테스트 1,103개(엔진 1,098 + portability 5), 실제 Chrome 브라우저 테스트 17개 통과. 실제 Chrome DevTools MCP 1.3.0과 scripted 모델로 동명 버튼 discover→freeze→replay, 포털 옵션 재생, 오래된 ref·동일 내용 노드 교체·구조 변경 거부, 팝업/위임 클릭 사실, 프레임 실패 격리와 ref 생략을 확인했다. 기존 테스트·픽스처는 수정하지 않았다.
- **state 변화:** #198의 공통 관측 정책과 요소 주소 지정 구현을 PR #221로 제출한다. 공개 계약은 `spec/core/perception.md`; 관측 간 영구 정체성 및 모든 DOM 노드 수집을 보장하지 않는다. `state.md`는 머지 후 develop에서 반영한다.
