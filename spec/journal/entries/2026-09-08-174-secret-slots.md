# 2026-09-08 — 비밀값은 실행 때 채우고 절대 얼리지 않는다 (#174)

- **브랜치:** `fix/174-secret-slots`.
- **문제:** `type` 스텝이 텍스트를 그대로 얼려 로그인 흐름의 비밀번호가 스킬 파일에 들어간다. CLI가 생기면서 스킬이
  저장소에 사니 "어색함"이 "실격"이 됐다. 그리고 #174 코멘트의 실측: 흐름이 결제 사업자 페이지로 넘어간 뒤 모델이 그쪽
  로그인 폼에 같은 자격증명을 넣으려 했다 — 프롬프트의 "우리 사이트에서만"은 부탁이지 보장이 아니다.
- **변경:** `{name}`(중괄호 속 맨 식별자만; JSON·템플릿은 통과)을 계약으로. `secrets: Record<string, string |
  { value, origin }>`를 `runScenario`·`runHarness`·`runSuite`·`discover`에, CLI는 `--secret name=value`(반복)·
  `--secret-origin name=url`·`CAIRN_SECRET_<NAME>`. `fillSecrets`가 드라이버에 넘길 값만 채우고 스텝(=스킬·트레이스·
  진행 이벤트)은 자리표시자 유지. 발견 때는 모델이 의도의 `{password}`를 되풀이하면 드라이버는 값을, 프리즈는
  자리표시자를 받는다 — 이미 얼린 리터럴을 슬롯으로 바꾸는 건 호스트 몫(엔진은 뭐가 비밀인지 모른다).
  fail-closed 둘: 값 없는 자리표시자 = 호스트 배선(`handler` → environment, exit 4); 범위 있는 비밀값을 origin 밖
  페이지(`onSiteOf`, #184의 경계)에서 요구하면 발견·재생 모두 거부 — 스텝 실패로 script(exit 3). 신규
  `spec/core/secrets.md`, guide "Secrets" 절. 두 엔트리에서 `fillSecrets`·`hasSecretPlaceholder`·타입 export.
  `cli-args`에 반복 플래그(`flagList`) 지원.
- **병렬 검증에서 고친 것:** (1) **유출:** 드라이버가 값을 친 다음 턴의 스냅샷이 일반 텍스트 입력(아이디·토큰·OTP·"비밀번호
  보기")의 값을 그대로 들고 와 LLM 프롬프트에 렌더링됐다(실제 Chrome으로 확인; `type=password`는 브라우저가 가림).
  `redactSecrets`로 프롬프트 전에 요소 name/value의 비밀값을 `{name}`으로 — discover와 step-heal 양쪽. (2) 모델이
  자리표시자 대신 리터럴을 되풀이하면 프리즈에 값이 박혔고 아무것도 안 막았다 → `slotSecrets`가 프리즈 전에(step-heal의
  수리 스텝에도) 되돌림. (3) 거부 메시지의 페이지 URL이 쿼리(콜백 토큰)를 통째로 실었다 → origin+path만.
  (4) `onSiteOf`가 포트를 무시해 `localhost:3000`의 비밀값이 `:4000`에서 허용 → origin에 포트가 있으면 일치 요구.
  (5) `--secret` 없이 `--heal` 재생하면 막힌 스텝이 outcome-heal을 유발해 LLM 재발견을 돌리고 최종 등급이 script로 —
  spec의 "environment, exit 4"와 어긋남 → environment 등급이면 heal 안 함(#186 논리 그대로). (6) 기존 스킬이 리터럴
  `{word}`를 치고 있었다면 이제 fail-closed되는 동작 변경 → `{{word}}` 이스케이프 추가하고 spec·guide에 명시.
  (7) 발견 중 값 없는 자리표시자는 모델이 우회할 수 없는 벽인데 스텝 예산을 다 태웠다 → 즉시 중단(rethrow).
  (8) 맨 `--secret`이 앞의 값들을 지웠다 → 유지하고 사용법 오류로. (9) 스킴 없는 `--secret-origin`은 매번 거부돼
  혼란 → 앞단에서 검증. (10) `LlmStepHealer`에 secrets가 안 넘어가 자리표시자 스텝은 heal 불가 → 생성자로 전달.
  (11) 자기 `stepHandlers`를 쓰는 소비자는 채움이 안 된다는 것을 옵션 문서에, README/spec 색인에 새 spec 행.
- **안 한 것:** 프리즈 시 자동 슬롯(엔진이 비밀을 판별할 수 없음) · 트레이스 페이로드의 별도 마스킹(값이 스텝에
  실리지 않으므로 필요 없음; 드라이버 호출 인자는 트레이스에 안 감).
- **검증:** `fillSecrets` 단위(채움·JSON 통과·값 없음→handler·범위 밖/미상 페이지 거부) + 재생 3(드라이버는 값,
  결과·스킬 어디에도 값 없음; 값 없음→environment; 범위 밖→script) + 발견 2(스킬은 자리표시자, 드라이버는 값;
