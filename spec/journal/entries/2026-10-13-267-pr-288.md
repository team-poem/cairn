# Require manual review-to-merge label transitions

_Drafted from [#288](https://github.com/team-poem/cairn/pull/288) by amazon7737. Edit this in place; do not delete and re-add it._

## What

Require a maintainer to remove `status/1-needs-review` and add `needs-merge` before cairn-pingu can merge an approved PR. A review label blocks merging even when `needs-merge` is also present, both at the initial check and immediately before the merge.

After GitHub confirms a successful merge, remove only `needs-merge`. A closed-PR event retries cleanup for an already merged develop PR without attempting another merge. Missing labels are an idempotent success; other cleanup failures remain visible.

## Why

Approval and passing CI must not silently advance a PR out of review. The maintainer owns the review-to-merge label transition, and completed merge requests should not retain an active request label. The bot never removes the review label or adds `needs-merge` on a maintainer's behalf.

The existing `no-merge`, approval, latest current-head CI, clean merge state, develop-only, and expected-head checks remain intact. Label cleanup uses the App's existing Pull requests write permission. Periodic scans still consider only open PRs; retry the closed-event job if post-merge cleanup fails.
