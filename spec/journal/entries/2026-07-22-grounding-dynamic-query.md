# 2026-07-22 — 소비자 발견: grounding이 실행-특정 쿼리를 굳혀 영구-FAIL 대본을 만듦

- **출처:** 한 소비자 앱 임베드 도그푸딩. 엔진 코드 변경 없음 — 관찰 저널.
- **실측:** 같은 행위 POST가 한 런에서 2회 발화하자(항목 2개 담기), grounding이 두 요청을 구분하려고
  **쿼리스트링까지 포함해** `…/cart/add-carts?buyRequestIds=586738` 형태로 단언을 굳힘. 그 쿼리 값은
  **런마다 새로 발급되는 일회성 ID** — 재생은 항상 새 ID로 발화하므로 이 단언은 어떤 재생도 영원히
  만족 불가(구조적 false FAIL). 1회 발화일 때는 경로 수준으로 굳어 문제없던 것이 복수 발화에서 발현.
- **연쇄 비용:** outcome-heal(재발견)도 무력 — 복구 판정 기준이 그 박제 단언이라 재발견이 무엇을 해도
  FAIL 확정. 12콜/65k 토큰 낭비 + 재발견의 재수행으로 서버 상태 오염(항목 중복 적재).
- **소비자 우회(적용됨):** 실행 직전 정규화에서 request-status 단언의 쿼리스트링을 벗기고(경로만),
  동일해진 단언은 dedup. 행위 검증은 경로로 충분하고 개수 정합은 앱별 상관 검증이 담당.
- **엔진 제안:** grounding이 urlIncludes를 **경로까지만** 굳히는 것을 기본으로 — 쿼리 값은 실행-특정
  동적 값(세션·발급 ID·타임스탬프)일 확률이 높아 재생-등급(replay-grade) 단언이 못 된다. 같은 경로
  N회 발화의 "횟수" 검증이 필요하면 쿼리 박제가 아니라 별도 표현(count?)이 맞음.
