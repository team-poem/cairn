# Measure foreground regions conservatively

_Drafted from [#311](https://github.com/team-poem/cairn/pull/311) by solp721. Edit this in place; do not delete and re-add it._

## What

Extract a shared, MCP-independent DOM probe and use it in Chrome perception capture.

- Recognize native dialogs, standalone ARIA dialogs, popovers and controlled popup regions without treating ordinary disclosures as popups.
- Detect markerless overlays conservatively using viewport coverage and hit-test evidence.
- Respect top-layer clipping boundaries and restored `visibility:visible`, while keeping genuinely clipped or unmeasurable candidates unknown.

Core ranking, exact-node references, duplicate ordinals and frozen replay semantics remain unchanged. The shared probe stays internal; no new public API is introduced.

## Why

Foreground controls can be omitted from the model's candidate cap while offscreen background controls remain eligible. Occlusion alone cannot resolve this.

This improves the measured `inActivePopup` facts without application-specific selectors or treating every fixed element as an overlay. Smaller markerless overlays and unsupported frame/shadow cases remain documented limitations.
