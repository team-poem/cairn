# 2026-08-26 — 소비자 발견: 승격 후보 목록 (CLI 도입을 감안한 우선순위)

- **출처:** 한 소비자 앱(브라우저 확장 형태의 임베드 호스트) 장기 도그푸딩. 각 항목은 그 호스트가
  **실제 사고를 겪고** 자기 층에 구현해 둔 것 — 가설이 아니라 운영 중인 코드다. 코드 변경 없음(제안).
- **리트머스:** 각 항목을 "다른 소비자도 원하나 / 앱 지식 없이 성립하나 / CLI에서 더 절실해지나"로 검증했다.
  앱 지식(특정 위젯 어댑터·도메인 맵·페이지 카드 내용)은 애초에 제외했다 — 불변식 #1.
- **CLI 렌즈가 순위를 바꾼 이유:** 임베드 호스트는 사람이 화면을 보며 실행하지만, CLI는 **사람 없이
  CI에서** 돌고 **frozen이 레포에 커밋**된다. 그래서 (a) 환경 이식성 (b) 비밀값 (c) 실패의 기계적 분류
  (d) 대본 청결이 "있으면 좋은 것"에서 "없으면 못 쓰는 것"으로 승격된다.

## Tier 1 — CLI가 오면 즉시 필요해지는 것

### 1. 실행 시점 재앵커 (frozen의 절대 URL을 실행 base로)
- **문제(실측):** freeze가 진입 goto·`navigated.to`·요청 단언에 **그때의 절대 URL을 박제**한다. 다른 환경에서
  재생하면 대본이 원래 환경으로 페이지를 끌고 간다(운영에서 돌렸는데 스테이징으로 점프한 사고).
  경계 가드는 같은 부모 도메인이라 침묵했다.
- **CLI:** `cairn run <case> --base-url http://localhost:3000` 은 CLI의 **기본** 사용 패턴(로컬/스테이징/CI).
  지금 계약이면 이 명령이 성립하지 않는다.
- **형태 제안:** 실행 옵션의 base로 페이지 URL을 재앵커(경로 유지), **요청 매칭은 호스트를 벗겨 경로만**
  — 게이트웨이 호스트는 환경마다 다르고 경로는 불변이다. 대상 호스트 집합은 소비자가 주는 설정
  (`allowedHosts`), 그 밖(외부 결제 등)은 불변. 경로가 안 남으면 원본 유지(fail-closed).
- **소비자 상태:** 실행 직전 순수 변환으로 구현, frozen 저장본은 불변(소급 적용됨).

### 2. 실행-특정 쿼리 박제 (2026-07-22 엔트리의 재확인)
- 같은 행위 POST가 한 런에서 2회 발화하자 grounding이 둘을 구분하려 **쿼리스트링까지** 굳혔고, 그 값이
  런마다 새로 발급되는 id라 **어떤 재생도 영원히 실패**했다. outcome-heal도 무력(판정 기준이 그 단언).
- **CLI:** 사람이 안 보므로 "영구 빨간불"이 그냥 깨진 파이프라인이 된다. 2.7.0에도 미수정.
- **형태 제안:** grounding의 `urlIncludes`를 **경로까지만**. 횟수 검증이 필요하면 쿼리 박제가 아니라 별도 표현.

### 3. 실패의 기계적 분류 (verdict에 실어주기)
- **문제(실측):** 같은 FAIL인데 사람이 할 일이 셋으로 갈린다 — ① 앱 기능이 깨짐 ② 대본이 낡음(화면 변경)
  ③ 실행 환경 문제(자격증명·API 한도). 소비자는 verdict·trace를 사후 해석해 분류기를 직접 짰다.
- **CLI:** 이건 **exit code 설계**다. CI는 ①이면 빌드를 세우고, ②면 재학습 잡을 돌리고, ③이면 재시도해야
  한다. 지금은 전부 `exit 1`이라 파이프라인이 세 경우를 구분할 수 없다.
- **분류 근거는 이미 엔진 안에 있다:** 스텝 실패 유무 · 요청이 *발화했는데* 비-2xx인지(`no request matching`
  이 아닌 실패) · 스텝 에러의 서명. 소비자는 이 셋으로 충분히 갈렸다.
- **형태 제안:** `Verdict.failure?: "flow" | "script" | "environment"`. 불확실하면 `flow`(가장 심각) — 소비자
  경험상 완화 쪽으로 기울면 진짜 회귀를 덮는다.

### 4. 비밀값 슬롯 1급화
- **문제:** freeze가 입력값을 그대로 굳히면 **비밀번호가 대본에 박힌다**. 소비자는 freeze 직후 값을
  `{name}` 슬롯으로 치환하고 실행 시 채우는 층을 직접 만들었다.
- **CLI:** frozen이 **레포에 커밋**되므로 선택이 아니라 필수다. `--secret`/env 주입과 자연히 맞물린다.
- **형태 제안:** `Step.text`의 `{name}` 플레이스홀더를 계약으로 인정 + 실행 옵션 `secrets: Record<string,string>`.
  freeze 쪽 자동 슬롯화는 "무엇이 비밀인지"를 엔진이 모르므로 소비자 몫으로 남겨도 된다 — **채우는 쪽만**
  1급이면 각 소비자가 재구현할 이유가 사라진다.

## Tier 2 — 드라이버 품질 (레퍼런스/CLI 드라이버가 똑같이 겪을 것)

### 5. 스냅샷 정온 게이트
- **문제(실측):** SPA가 스켈레톤을 먼저 그리고 데이터를 나중에 채우는데 idle 판정이 fetch 갭에 속아
  **미완성 화면이 모델에 전달**된다 → 모델은 "없으니 스크롤"로 판단해 헤맨다. 프롬프트로 "기다려라"를
  시켰더니 waitFor 스텝이 늘어 **더 느려졌다**(LLM 왕복 추가) — 기계적 해결이 정답이었다.
- **형태:** 스냅샷 직전 활동이 잦아들 때까지 대기(상한 있음 — 웹소켓류는 상한 탈출) 후 요소 서명 수렴을
  1회 재확인. 평시 비용 0. CLI/headless는 더 빨리 도착해 스켈레톤 확률이 오히려 높다.

### 6. 클릭 도달 가능성(occlusion)으로 동명 해석
- **문제(실측):** 모달의 제출 버튼과 배경 네비 링크가 같은 이름일 때, 재생 resolve가 트리 순서상 먼저인
  **배경 링크**를 집어 페이지를 이탈했다. 마커 기반 판별은 실패했다 — 그 앱 모달엔 `role=dialog`가 없다.
- **형태:** 동명 다수이고 `nth`가 없을 때, 중심점 hit-test로 **실제 클릭이 닿는 후보**를 우선. 백드롭에
  가려진 배경·숨김 요소가 자연 탈락한다. 아무도 안 닿으면 기존 첫 후보(fail-safe).
- **#127과의 관계:** ambiguity gate는 *discover*가 모호성을 모델에 되묻는 것이고, 이건 *replay*(모델 없음)가
  물리적으로 하나를 고르는 것 — 대체가 아니라 상보.

### 7. 워터마크 방식 select
- 커스텀 드롭다운을 열기 **전** 노드 집합을 찍어두고, 연 뒤 **새로 등장한** option만 후보로 본다. 페이지
  어딘가에 상시 존재하는 동명 option을 오매칭하지 않는다. select가 1급이 된 지금 레퍼런스 구현 품질 항목.

## Tier 3 — 대본 청결 (엔진 로드맵 ③과 겹침)

### 8. 관찰 기반 무효 스텝 가지치기
- **문제(실측):** discover가 헤매며 밟은 스크롤이 frozen에 그대로 굳어, 재생마다 재현되며 **네트워크 속도에
  따라 결과를 가른다**(빠르면 통과·느리면 실패). 대본 끝의 스크롤은 검증 화면을 벗어나게 만들기도 했다.
- **판별은 관찰로 결정적으로 된다:** 스크롤의 유일한 기능적 효과는 lazy-load 요청 유발이다(뷰포트 이동은
  재생에서 무의미 — 클릭이 scrollIntoView를 자체 수행). **요청을 하나도 만들지 않은 스크롤은 헤맴 잔재.**
  모델 판단이 필요 없다.
- **엔진이 더 잘한다:** 소비자는 스텝별 요청 수를 밖에서 세느라 인덱스 오프셋 정렬 같은 취약한 보정을
  해야 했다. 엔진은 스텝별 evidence 델타를 이미 갖고 있다.
- **CLI:** 대본이 레포에 커밋되므로 군더더기 스텝은 diff 노이즈이자 매 실행의 시간이다.
- **한계(정직):** 클릭·입력류 헛동작은 DOM-only 효과가 있을 수 있어 관찰만으론 못 가른다 — 스크롤만이
  안전한 부분집합이다.

## 승격 부적합 (소비자가 계속 들고 갈 것)
- 특정 위젯의 상태 읽기/조작 어댑터, 앱 고유 상관 검증(행위가 발급한 id를 후속 상태에서 확인),
  합성 컨트롤, 도메인 어휘 맵, 페이지 카드의 **내용** — 전부 앱 지식(불변식 #1).
- 실행 중 입력 차단 오버레이·결과 표시 — 호스트 UX(경계 원칙: 앱 기능은 호스트).
- 클릭 가능 요소 승격의 **프레임워크 특정 부분**(위임 핸들러 탐지) — 보편 규칙은 이미 #132에 있고, 그
  위의 정밀화는 프레임워크 어댑터 성격이라 `perceive` seam으로 소비자가 얹는 게 맞다.

## 한 줄 요약
CLI가 오면 **1·3·4**(환경 이식·실패 분류·비밀값)는 "있으면 좋은 것"이 아니라 **CLI가 성립하기 위한 전제**가
된다. **2**는 그대로 두면 CI가 영구 빨간불을 맞는다. **5~8**은 어느 소비자든 자기 드라이버에서 같은 사고를
겪고 같은 코드를 다시 쓰게 되는 부류다.
