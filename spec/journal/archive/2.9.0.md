# 2.9.0

60 entries from the 2.9.0 cycle. The release theme was a green that has to prove itself, and a
benchmark instead of a claim.

## JsonlTraceSink drops writes offered after close instead of racing them
*#199*

`close()` awaited the queue only as it stood when it was called, while `emit()` and `attach()` kept
chaining fresh flushes onto it. `close()` now sets a closed flag once a path exists, so a close
before any header stays a no-op, and post-close writes are dropped deterministically while
incrementing the failure count, because a truncated trace must not read as a clean one. There is no
known production emit-after-close path, so the guard is defensive against a caller-contract
violation. The truncation test was rewritten to assert the real invariant at `appendFile` time,
verified by temporarily swapping two awaits and watching it go red.

## urlIncludes matches query parameters as an order-independent subset
*#200 · PR #201*

`findRequestStatus` checked `urlIncludes` as a plain substring, which let a frozen `?op=AddToCart` be
silently satisfied by `?op=AddToCartV2`, lost the query when a trailing slash broke the prefix guard,
and failed on reordered parameters. `urlMatchesFrozen` keeps substring matching before `?` and does
subset matching on parsed pairs after it: all frozen pairs must be present with the same value, extra
parameters allowed, order irrelevant. The four hand-rolled containment checks were replaced with it
so verification and diagnostics cannot diverge. Review caught a real regression: `hasStablePath`
still tested for a slash anywhere, so a prefix carrying a query path disarmed both the host-only
check and the unproven-action gate.

## Bounded redirect observation plus the fallback advisory marker
*#203 · PR #205*

An advisory alone left the concrete response-to-redirect race unmitigated, so the fix combines a
bounded observation with the provenance marker rather than choosing between them. Final observation
shares its existing two-second budget between pending flow mutations and a completed, non-benign,
same-site mutation whose step's pre-action URL still names the current host and path. Query and hash
progress do not count as a destination change, every continuation yields a capped sleep so a
continuously changing URL cannot hot-loop, and remaining time reaches `Driver.settle`. The trace
header moved to 1.3, and the type, specs and CLI all state that the marker alone must not become a
failure gate without additional evidence, since a correct on-page save legitimately consumes the
budget and carries the advisory.

## navigated assertions record the destination observed before the last mutation
*#203*

Discovery can submit a successful POST and freeze the form URL before the app's delayed redirect, so
a surviving POST assertion proves the request but not the redirect. `observedBeforeLastMutation`
belongs only to the `navigated` variant and records that the grounded destination already matched the
URL observed before the last executed step with a qualifying mutation in its request tail, where
qualifying means a final status of 200 to 399, a mutation method, non-benign traffic and same-site. A
reverse scan preserves that boundary through trailing scroll and wait steps, and user-origin
assertions are never stamped. The marker is evidence provenance, not proof that a navigation is
pending or mutation-caused.

## Failures are classified as flow, script or environment with distinct exit codes
*#173 · PR #211*

One failure meant three different next actions, and the engine held every distinguishing signal while
exposing none. `Verdict.failure` is stamped on reds only and derived purely from existing signals,
applied in `finalizeVerdict` so replay and outcome-heal inherit it. Rule order: a blocked step is
script, or environment if the error names the browser or transport; a proofless freeze is script; a
judge failure is environment; a goal failure is flow unless every failed goal was a request rejected
with 401, 403 or 429; then guard-only; then flow by default, tilting to flow when uncertain so
regressions are never buried as retries. CLI exit codes are 0, 1 for flow, 3 for script and 4 for
environment, with 2 reserved for usage. A 5xx was deliberately left as flow, because a status code
alone cannot separate an app regression from an infrastructure outage. Review found the same root
defect repeatedly, free-text matching over rendered strings, which became the motivation for #212.

## Idle scroll steps are pruned from the freeze
*#177 · PR #210*

Scrolls taken while discovery wandered froze into the skill and were re-executed on every replay,
where a trailing scroll's verdict depends on network speed. But zero requests does not mean
meaningless, since a virtualized list only mounts its next target after a scroll. A scroll is removed
only when its request tail is empty and the next step's target was already present in the snapshot
taken immediately before it; a trailing scroll with no following step is removed on zero requests
alone, and a following step with no target blocks the judgment. Verification caught that presence
must read `nth` only and not fall back to `index`, and that disabled elements must count as absent,
otherwise a scroll-to-enable is pruned, replay clicks a dead button, and heal reruns the same
discovery in an infinite loop. The trace version went 1.3 to 1.4.

## Heal verdict helpers exported from both public entries
*#195*

The rule #186 established for when a rediscovery counts as a heal lived solely inside the pipeline,
so a consumer running its own rediscovery had to reimplement it, and the most natural
reimplementation is exactly the predicate #189 rejected on measurements. `goalFailures`,
`finalizeVerdict` and `blockedReason` are now exported from both entries; they are pure, so the
browser entry is safe. A consumer heal written using only the browser entry matched the built-in
across seven cases. The export lets consumers reimplement correctly but not inherit: three of the six
stages in `run.ts` are still not carried, which makes a composable `outcomeHeal` the follow-up.

## Destination misses say when the matcher lacks a configured prefix
*#204*

A `navigated` miss reported the same wording whether the app went elsewhere or the matcher simply did
not know this app's leading segment, so a configuration gap read as a regression.
`unrecognizedLeadingSegment` returns a segment only when stripping exactly one leading segment, tried
on both sides and never guessing two, would have made the URL match; the critic appends a hint and
the verdict itself is unchanged. The issue's proposed condition was deliberately narrowed, because
over the corpus's 19 unreached rows it would have fired on 15, all false positives, while the final
rule fires on none. Two follow-ups were logged: the CLI has no flag to pass `localePrefixes`, so the
hint points CLI users at something they cannot configure.

## Embedding example runs through the public package boundary
*#8*

Consumers must be able to go from install to replay without depending on engine-internal files, so
the CLI was cleaned up to use only public entries and a dependency-direction check was added. A
standalone quickstart installs the npm package and runs discover, freeze and replay, and CI verifies

## Frozen scenarios can be replayed against a different environment
*#171 · PR #215*

Freeze stores absolute URLs and host-bearing conditions, so replaying elsewhere either visited the
original environment or failed incorrectly. `replayEnvironment { baseUrl, allowedHosts }` accepts
HTTP origins only and limits rewriting to an exact host list, preserving path, query, hash, bare
forms and wildcards. Frozen request expectation strings are never rewritten: path prefix and query
subset are compared only when both hosts are allowed, and cross-environment fallback for host-only
conditions is forbidden. Heal in the target environment is temporary, so `healedScenario` is never
returned on any path, and a suite replays only the newest cache for the original case hash, failing
before any browser or LLM work rather than rediscovering. Review reproduced three behaviours through
real API calls, and the root design error was applying the same conservative boundary to page
destinations and request expectations: a host-only page destination is the normal shape freeze stores
for a root URL, so it is translated, while the ban stays for request expectations.

## Secrets are slotted at decision time and never frozen
*#174 · PR #218*

`type` steps froze their text literally, so a login flow's password ended up in the skill file, and a
comment measured the model carrying the same credentials into a payment provider's login form once
the flow left the site: the prompt's "only on our site" is a request, not a guarantee. The contract
is `{name}` with `{{name}}` escaping, accepted by the library entries and by the CLI as repeatable
flags or environment variables; steps, and therefore skills, traces and progress events, keep the
placeholder while only the driver receives the value. Two fail-closed rules: a placeholder with no
value is host miswiring, and a scoped secret demanded outside its origin is rejected in both
discovery and replay. Review moved slotting to decision time in `applyDecision`, so a model echoing
the literal instead of the placeholder is still scope-checked and scrubbed before execution, storage,
trace and the next prompt, with filling done in exactly one place. A single-pass matcher handles
secrets longest-first, escapes and existing placeholders in one scan, so a value containing braces
cannot escape scope checking. Masking covers element values but never accessible names, which are the
page's own text and locators. Automatic slotting at freeze time was not done, because the engine
cannot tell what is secret.

## Passing verdicts carry a proof grade
*#197 · PR #217*

A green earned from a 2xx mutation and a green earned from a matching final URL were both just
`{ passed: true }`. `Verdict.proof` is graded by `proofOf` purely from metadata freeze already
stamps, into `work`, `judged`, `arrival` or `none`, alongside counts. Guards are counted separately
and excluded from the vacuous and discriminating tallies, because #137 always marks them vacuous on a
clean start yet they genuinely go red on a 500 mid-flow. `provesAnAction` is now implemented in terms
of `proofOf`, so the #184 gate and the grade cannot diverge. The grade is advisory: no fail-closed
gate is built on it, and old skills without stamps will over-grade a landing-page GET as `work`,
documented as the only consistent choice.

## Classification signals moved from prose strings into typed fields
*#212 · PR #213*

The #173 classifier read human-facing detail strings with regexes, and all eleven findings in that
review came from it; anchoring held, but a single wording change would silently unhook it. Signals
are now carried as fields: `AssertionResult.statuses` and `reason`, `Verdict.failClosed` and
`ExecutedAction.errorKind`, with error kinds set at the throw site via `stepError(kind, msg)`, a
plain property on the Error so an external driver can throw one without importing anything. The
Chrome driver classifies its own MCP envelope, and `classifyFailure` contains zero regexes. An
unclassified throw is script: when nothing is said, take the noisier side. Review found the one path
by which page text enters the envelope is a dialog, so dialog blocking is recognized before the
transport check. The trace went 1.4 to 1.5.

## Shared perception policy and observation-time element addressing
*#198 · PR #221*

Portal options appended at the end were being cut by the prompt budget, and execution that re-found
an element by name could pick a different node than the one observed. Optional Driver observation
facts plus a transient `ref` were added, and discover, explore, step-heal and locator-heal now share
one observation and selection policy, with popup priority, click-region deduplication and evidence
reservation owned by the engine and DOM measurement owned by the Driver. The addressing contract
gives the model a per-observation token table and hides the real Driver ref, runs policy checks
against the actual name, role and duplicate ordinal in the full snapshot, re-validates immediately
before execution, and never reinterprets a failed ref by name. Freeze keeps only the existing Target
fields and replay runs without an LLM. If even one candidate sits outside the watched scope, shadow
DOM or frames, the safety of shared ordinals cannot be guaranteed, so refs are omitted for the whole
observation. The public contract is `spec/core/perception.md`, which does not promise identity across
observations.

The branch went through four review rounds. Blocking findings, all reproduced and fixed: a perception
capture left the verbose tree in the driver's cache, so freeze counted ordinals over one pool while
replay resolved over another, and the same cache broke `select` on a custom dropdown; and the
observation constructor threw from outside the loop's try, so a `perceive` hook that trimmed a name
killed the whole run. Later rounds fixed a stale watermark after a successful retry, a truncation
notice that counted rows scrolling can never reveal, binding rejections reported to the model as JSON
syntax errors, a locator-heal prompt teaching a schema its own parser rejects, and reference binding
rejections emitting nothing to the trace. A later performance round negotiated an observation
capability with the MCP server and skipped the post-script DOM wait for negotiated calls, which was
measured to change what is observed rather than only how fast, so a readiness evaluation was added
before the guard install. The measured cost of an exact-ref action settled at 14 calls and about
977ms against 4 calls and about 445ms for the legacy path. Four items were left as follow-ups:
`resolveTargetUid` indexing `nth` over a different pool across attempts, amplification on a server
that advertises the capability then stops honouring it, `ensureConnected` having no in-flight memo,
and an iframe dropping exact refs for a whole capture.

## Cost benchmark with two arms sharing one schedule and budget
*#214 · PR #223*

A `cost` mode was added: the `agent` arm rediscovers on every run, the `cairn` arm discovers once and
replays, repairing when the app changes and carrying that repair forward, with both arms sharing the
same tiers, change schedule and budget. Change points are set per run via `fixtureVersions`, so both
arms hit the same change on the same run. The two arms of a tier share one reserved port so the
capture's fixed URLs still match later runs and no replay environment is needed, which matters
because #171 deliberately withholds `healedScenario` when a replay environment is configured, and
without re-freezing the `cairn` arm would pay for the same breakage on every run. The report withholds
the crossover whenever it would be a claim rather than a measurement: scripted provenance means no
paid calls, an arm that did not finish the schedule was never compared on it, a run with no reported
cost would enter the sum as zero and score an unknown as free, and a failed run costs nothing so a
broken arm looks like the cheap one. Run 1 is excluded because both arms do the same work on the same
fixture, and a tie is not a crossover. A replay that returns no usage, or an engine-reported call the
bench did not observe, marks the run failed, since free is a claim about money that both viewpoints
must agree on. Discovered or repaired scenarios that leave the fixture origin are rejected, because
this path has neither `loadCapture` nor an allowed-host list. Cache-creation tokens were added to the
bench's own accounting because they are billed, and the "full agent $15 to $30 per run" comparison was
deleted from the guide and the design doc as a number nobody ever measured.

## The element listing is sent on every turn
*#225 · PR #226*

Discovery and explore replaced the page element listing with a single `(unchanged from previous
step)` line whenever the render matched the previous turn, a premise that assumes the model can look
back. `LlmClient` is a single conversation-free `complete(prompt)` and all five shipped backends send
an independent request per call, so from the second turn on the model was deciding with a sentence
pointing at a listing it had never seen. One action that does not change the page, a `waitFor`, a
scroll that revealed nothing, a rejected action, blinds the next turn, and a blinded turn has nothing
to act on, so the loop cannot recover. With a real model over three local fixtures run six times
each, the single-click tier passed 12 of 12, the type-then-save tier failed 12 of 12, and login,
cart, order burned 15 to 21 calls without completing; the failing runs were those whose first
decision was a `waitFor`, and the model's stated reason was that no list of interactive elements was
provided. The returned scenarios had no actions and entirely vacuous checks, so replay would close at
the all-vacuous gate. Everything below perception worked; the journey simply never happened. It went
unseen because these fixtures had only been run with the scripted client, which does not read the
prompt. The listing is capped at 60 and describes only the current page, costing about 21 tokens per
turn on a small form and about 510 at the cap, against more than 5,000 already exchanged per call
with a cached system prompt, while one failed discovery burns 5 to 11 paid calls and leaves an
unreplayable scenario. System-prompt caching, the other half of the same #15 work, is kept.

## Per-PR performance comparison and OS compatibility checks
*#220 · PR #227*

Workspace and offline bench test commands were split while preserving the local aggregate. The
comparison measures exact base and head package and browser bundle bytes plus three local replay
tiers, and native build and browser compatibility runs on Ubuntu, macOS and Windows. A baseline
fixture, runner and scripted discovery produce shared canonical captures, both built engines warm up
and alternate over measured rounds with fixed delays, and failures, incomplete samples or unknown or
nonzero replay LLM usage invalidate the comparison, with timing kept informational. Reporting goes to
the Actions summary and artifacts plus a separate trusted `workflow_run` publisher that recomputes
from validated JSON, checks current SHAs and bot ownership, and never executes PR artifact code with
a write token.

Review found two blocking problems, both fixed. Three rounds could not balance position, so under any
monotone drift each side's median came from a fixed slot and the delta carried a deterministic sign;
sampling moved to four rounds in AB/BA/AB/BA order, which cancels linear drift exactly and leaves
only curvature, about 0.2 to 0.4 percent. And a fork could make the repository's bot publish
fabricated numbers, because the measurement coordinator runs from the PR head and the freshness check
compared the artifact's self-declared SHAs against the real ones, which the fork knows; the comment
job is now gated on the head repository being this repository, so a fork never mints a token and its
results stay in the Actions summary. A later round removed p95 from the comment, since at four
samples it is exactly the maximum and base always holds the last slot.

## Local reliability measurement runner for discovery, replay and repair
*#169 · PR #222*

A runner separating discovery, replay and repair, with three tiers: simple navigation, asynchronous
form save, and login, cart, order. Each attempt owns a fresh server and an isolated browser and waits
for cleanup. Delays are fixed by path kind and attempt index, with the requested delay and the
observed time recorded separately. Discovery stores the Scenario the public engine produced along
with its provenance and hash; replay blocks LLM calls, keeps the original and connects to the new
server address, preserving engine verdict and the server's completion state separately and reporting
all attempts including exceptions as JSON and Markdown. The real-measurement interface requires
explicit model, call-count and cost stop criteria, sums the known cost of failed calls, and halts
further paid calls when cost is unclear, a post-hoc criterion that can overshoot by one call, so it
is not presented as a billing cap. Scripted discovery checks engine integration and must not be
conflated with a real LLM discovery success rate. A later round fixed reporting of aborts and budget
stops, and narrowed interpretation: a frozen `waitFor.text` checks the captured text condition, so a
failure on a specific text change must not be generalized as fragility of the tier itself.

## Cost reported per model, with charts generated from the report
*#170 · PR #228*

One CLI invocation bills two models: alongside the model under measurement, the tool runs its own
smaller background model, about one eighth of the total on the navigation tier, so a single total
cannot answer what the measured model cost. Each run now stores the provider's per-model breakdown
and the report emits one row per arm and model, while the arm's cost column keeps the total, which is
the money actually spent. The breakdown arrives with the provider's cost basis, confirmed to be list
price, so a subscription-authenticated run's cost is already the API equivalent and no local price
table is kept, since one would go stale and produce wrong numbers. Charts are generated from the
report alone so any README graph can be rebuilt from the data that produced it, and a tier the report
judges to have no crossover gets no picture, because a claim made in a picture is still a claim.

A cost estimate was off by twentyfold: the budget was extrapolated from an earlier journal
measurement against a real multi-step checkout, giving $80 to $110 for two models, whereas the pilot
measured six navigation runs over two arms at 21 calls for $0.167, about $0.008 per call, with Opus
only 15 percent above Sonnet. The lesson recorded is not to multiply a unit price measured under
different conditions, but to measure the cheapest tier once under a low cap and extrapolate.

## The real cost measurement, and what it did not measure
*#170 · PR #228*

Run against develop with #225 fixed and #221 and #227 merged: three tiers, six runs per arm, Sonnet 5
and Opus 5, app changing on run 4, 72 attempts and no failures, at $0.617 for Sonnet and $1.076 for
Opus. Rediscover-every-run against discover-once-then-replay was $0.109 over 18 calls versus $0.018
over 3 for navigation, $0.151 over 24 versus $0.025 over 4 for the form, and $0.269 over 42 versus
$0.046 over 7 for the checkout, with Opus at $0.208, $0.255 and $0.463 against $0.030, $0.042 and
$0.077. All six crossed over on run 2, and the multiple barely moves with the model because the
saving comes from call count and not unit price: five of six runs make no call at all.

**No repair ever fired.** v2 genuinely renames labels, four of five actions in the checkout flow, but
the frozen targets survive because they carry more than a name: `{"text":"Log in","role":"button",

pilot got cheaper after #221, 21 calls at $0.167 before against $0.132 after with replay elapsed down
from 2,496ms to 2,327ms, so the concern that #221's reference path adds round trips per action did
not raise whole-discovery cost.

## A second provider measured, and the presentation lesson it produced
*#228*

A Codex path was added to the bench adapter. A real pilot returned input, output and cache tokens but
no cost, so a call-only budget mode was added that limits a run by an explicit call count, cannot be
declared together with a dollar limit, and leaves unknown cost unknown. Model calls run in a
temporary directory with user config, project instructions, shell, web and session storage disabled.
Sol, Terra and Luna then measured 108 of 108 successes with all 45 replays at zero calls and zero
repairs, 300 calls in total, every one reporting token fields and none reporting a dollar cost, so
the cost comparison, crossover and chart were withheld. Six-run checkout figures were 42 calls and
506,120 tokens against 7 calls and 84,088 for Sol, 504,711 against 83,956 for Terra, and 448,690
against 74,978 for Luna, with Luna's form tier at 30 calls against 4, preserved as observed rather
than assumed to follow a constant ratio. Dollar estimates were later derived from those tokens using
published list prices confirmed on a stated date, with the tier treated as an assumption because the
CLI reported neither cost nor tier.

The README section was then revised roughly fifteen times, which is the durable lesson. A table
placing per-model dollar figures side by side reads as a model price ranking however carefully it is
footnoted, so the landing page ended with a short description and one cumulative-call chart per
provider, each showing the same 7 to 42 against 7 trend per model rather than summing or averaging
across models, with dollar tables and conversion bases moved into the detailed document. Footnotes
about measurement conditions cannot prevent the comparison a table invites: an introduction page
should show the comparison axis being argued, and different cost-aggregation bases belong in the
detail. That distinction is now encoded both in the document structure and in the chart generator.

## Self-heal measured with a v3 fixture the locator fallback cannot absorb
*#230 · PR #233*

The benchmark never triggered a repair because role and position fallback absorbed v2's renames, so
v3 turns the checkout cart's `Place order` from a button into a link while keeping the name, the
order POST and the completion condition, leaving all other labels at v1 and rejecting v3 for other
tiers. The cost summary gained phases, discovery, repair and replay, with repair attempts counted
toward cost whether or not they re-freeze.

Across five models the result is the same: each repaired in one call and then replayed twice with no
call at all. Claude passed 24 of 24 with repairs 2 of 2: Sonnet discovery $0.042799 over 7 calls,
repair $0.006370 over 1 call, six-run cairn $0.049169 over 8 calls against agent $0.265392 over 42;
Opus discovery $0.087434 over 7, repair $0.013444 over 1, cumulative $0.100878 over 8 against
$0.545089 over 42. The three Codex models passed 36 of 36 with repairs 3 of 3, at 11,417, 11,421 and
9,994 repair tokens on one call each. Combined, 60 of 60 with repairs 5 of 5 and post-repair replays
10 of 10 at zero calls.

Replaying the same freeze with the model forbidden passes on v1 and fails on v3 at
`step 6/6 blocked: no element matching {"text":"Place order","role":"button","index":0}`, which is
the direct evidence that v3 defeats the fallback. Neither model froze a request-status for the order
endpoint, so goal achievement was confirmed separately by the fixture oracle. No engine code was
touched; the build hash matches #228.

## 2.9.0 release
*#173 · #197 · #200 · #203 · #212 · #225 · #229 · #230 · #231*

Twenty-one pull requests, 232 files, 17,832 lines added, no breaking change, trace contract 1.2 to
1.6, and skill files frozen under 2.8.0 still replay. Two threads ran through it. Judgment: proof
grades on passes, failure classes with distinct exit codes, structured signals replacing prose
matching, the pre-mutation destination marker, and query-subset request matching. Measurement: the
unmeasured per-run agent cost claim was deleted and a benchmark replaced it, with 42 calls against 7
across five models and two providers, every replay at zero calls and no failures across 180 attempts,
and a report that withholds any number it cannot stand behind. Running the bench with a real model

different pool and returning a differently named element, #230 for the self-heal measurement, which
landed at the end of the cycle, and #231 for the connection memo, capability amplification, iframe
references and CI test gaps.
