# Squash merge approved develop PRs labeled Merge as cairn-pingu

The case-sensitive `Merge` label requests a squash merge through GitHub's pull-request
merge API. GitHub preserves the PR author's attribution and records the App as merger;
the workflow does not manufacture an author identity or push a synthetic commit.

The installed App can bypass repository rulesets, so API permission alone is not a
merge gate. The workflow explicitly checks GitHub's approved review decision and clean
merge state, verifies the latest pull-request CI workflow succeeded on the current head,
then rereads the PR and passes that head SHA to the merge endpoint. A removed label,
withdrawn approval, draft, changed head, failed CI, or conflict leaves the PR open.
Only `develop` is eligible; release merges to `main` stay manual.

The App's existing Contents write and Pull requests write permissions are enough.
The workflow reads CI with its own read-only Actions token because the installed App
has no Actions permission. Privileged execution checks out trusted `develop` code and
never runs PR code or artifacts.

Label and same-repository review events work after the change lands on `develop`.
CI-completion and scheduled retries require the workflow on the default branch, `main`.
Fork review events cannot receive secrets and therefore rely on these retries. Native
GitHub auto-merge remains unnecessary. The repository's `Merge` label was created.
